## 실제 SDK 입력 경로 보완

직접 `tool.Call`만 부르던 선택 평가 시험을 실제 SDK 세션·`harness.execOne`·진단 도구 래퍼를 거치도록 바꿨다. 수정 전에는 null·잘못된 선택 타입으로 후보가 사라지고 긴 한국어 근거의 등급이 생략되는 반례가 실패했다.

이 도구만 `RawInput`을 사용하고, 내부에서는 새 평가 두 칸을 제외한 필수 네 필드와 기존 선택 필드를 core 스키마로 검증한다. 미등록 필드·뒤따르는 JSON·후보 결속 검사는 유지한다. null·잘못된 필수 타입·필수 누락·출처 위조·기존 선택 필드 null은 계속 거부한다. 제공자 입력 스키마·권한 검사는 바꾸지 않는다.

근거는 실행 보호 값과 DLP를 먼저 가린 뒤 UTF-8 글자 경계에서 자르고 `[근거 일부 생략]`을 붙인다. 1,023바이트 한국어 양성 대조, 1KiB 초과 한국어, 4바이트 문자와 경계에 걸친 보호 값을 검증한다. 긴 영문이나 자르는 경계 밖의 줄바꿈도 생략 문구로 유효화하지 않는다. 실제 관찰의 잘림·증거 digest는 그대로다.

새 일회용 PostgreSQL 16에서 agent 전체와 db/report/server의 심각도·관련 호출 집중 시험이 **일반 419 PASS / 0 FAIL / 0 SKIP**, 네 패키지의 집중 race가 **49 PASS / 0 FAIL / 0 SKIP**다. 별도 복사본에서 RawInput 해제, 바이트 자르기 제거, 가림/자르기 순서 교환, core 스키마 검사 제거를 각각 검출했다(**4/4**). 앞의 변이 실행이나 전체 시험 기록과 합산하지 않는다. 전체 Go build·vet도 통과했다.
