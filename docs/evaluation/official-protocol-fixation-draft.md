# 공식 측정 프로토콜 고정 초안 — 열린 항목 모음

상태: **초안, 결정 전**. 최민준 작성, 결정은 사용자가 한다. 이 문서는 흩어진 열린 항목을 한곳에 모아 항목마다 선택지·추천·근거를 붙인 것이다. 결정된 항목은 정본 문서([평가 프로토콜](evaluation-protocol.md) §5.1·§6, [탐색 분리 배치 결정안](exploration-split-decision.md), [공식 회차 절차](official-run.md), [개발 계획](../development-plan.md))에 옮기고, 이 문서에는 결정과 반영 위치만 남긴다. 이 문서가 정본 문서와 다르면 정본 문서가 이긴다.

기준: dev `628efa5b`. 열린 PR 중 같은 주제를 다루는 것은 #673(도구 면 측정)·#676(보존 sidecar v3)·#678(결정안 §10 열린 항목 추가)이다. 이 문서는 그 문서들을 고치지 않고 인용만 한다.

표시: **지금 결정** = 지금 있는 근거로 정할 수 있음. **파일럿 뒤 결정** = 파일럿 기록이 있어야 값이나 방향을 정할 수 있음. 추천에 적은 수치는 이미 잰 값이며, 측정 전 추정 수치는 적지 않는다.

## 1. 어느 상한이 먼저 걸리길 의도하나 (`first_limit`)

- **지금 상태**: 회차마다 `first_limit`(engine_completed / runner_request_budget / runner_time_budget / product_limit:<사유>)를 남기는 것까지 정했다(결정안 §3, [러너](runner.md)). 어느 상한을 의도하는지는 열려 있다(결정안 §10).
- **선택지**
  - (가) 러너 요청 예산이 먼저: 같은 대상 요청 수에서 무엇을 찾았는지 비교한다. 시간 예산은 안전 상한으로 둔다.
  - (나) 시간 예산이 먼저: 같은 시간에서 비교한다. 요청 예산은 크게 둔다.
  - (다) 엔진 완료가 먼저: 두 예산을 모두 크게 두고 엔진이 스스로 끝날 때까지 본다.
- **추천**: (가).
- **근거**
  - 계측기는 실제로 대상에 전달된 요청만 센다. E②가 거부한 요청은 세지 않으므로, 같은 전달 수 안에서의 비교에는 통제 비용(거부·보류)이 결과 차이로 드러난다.
  - 시간 기준은 O의 샌드박스·경계 지연이 그대로 섞인다.
  - (다)는 회차 길이와 비용을 미리 묶을 수 없다.
  - 파일럿(VAmPI, 600초·100건)에서는 1차 O와 재실행 B·O가 요청 예산으로 끝났다(재실행 B 140초, O 81초). 1차 B만 시간 예산으로 끝났는데, 엔진이 멈춘 뒤였다(결정안 §8).
- **파일럿 뒤 결정**: 공식 예산(§10)에서도 요청 예산이 먼저 걸리는지 확인한다. 시간 예산이 먼저 걸린 회차도 유효로 두되 `first_limit`별로 따로 집계한다.

## 2. 멈춤 무효 T값 (`provider_fault_stall`)

- **지금 상태**: 무효 조건 셋은 정해졌다(결정안 §7: 제공자 장애 기록 + T초 동안 모델·대상 요청 0 + 엔진 끝 신호 없음, B·O 같게, 무효 수는 늘 기록). T값은 "파일럿 기록으로 정해 측정 전에 고정"으로 열려 있다. 결정안 §7은 아직 평가 프로토콜 §5.1로 옮기지 않았다.
- **선택지**
  - (가) 정상 구간 최장 공백보다 크고, 관측된 멈춤 구간보다 작은 값에서 고른다.
  - (나) 원본 Planner 심장박동(600초)에 맞춘다.
- **추천**: (가). 정상 구간 최장 공백에는 대상 요청 없이 긴 명령을 도는 구간도 넣어 잰다(결정안 §7).
- **근거**
  - 지금 기록은 2쌍뿐이다. 정상 최장 공백은 1차 B 2.0초·O 0.9초, 재실행 B 3.0초·O 0.9초였고, 1차 B의 멈춤은 약 359초였다.
  - (나)는 멈춘 회차가 심장박동까지 대상 요청 없이 남는 것을 그대로 받아들이는 값이라, 이 규칙을 둔 이유와 맞지 않는다.
- **파일럿 뒤 결정**: 값. 공식 예산의 파일럿에서 긴 명령 공백이 늘어날 수 있으니, 공식 예산 파일럿 기록으로 정한다.

## 3. 무효 비율 상한

- **지금 상태**: "쪽별 무효 비율이 상한을 넘으면 측정 전체 실패"까지 정했고(결정안 §7), 값은 파일럿 뒤로 열려 있다. 평가 프로토콜 §5.1의 2N 규칙과 다르다(§0).
- **선택지**
  - (가) 2N 규칙만 둔다(조건 미완).
  - (나) `provider_fault_stall` 비율 상한만 둔다(측정 전체 실패).
  - (다) 둘 다 둔다. 2N은 모든 무효 사유에, 비율 상한은 `provider_fault_stall`에.
- **추천**: (다).
- **근거**: 2N은 고장 난 조건을 계속 돌리지 않게 막는다. 비율 상한은 한쪽만 자주 깨질 때 그 회차들을 골라 남기는 효과를 막는다. 막는 대상이 서로 다르다.
- **파일럿 뒤 결정**: 비율 값. 지금은 2쌍뿐이라 근거가 없다.

## 4. 엔진 끝 신호가 오면 회차를 끝낼지

- **지금 상태**: 러너는 끝 신호를 기록만 하고 회차를 일찍 끝내지 않는다([러너](runner.md), 결정안 §3.1). 이 동작을 바꿀지는 어느 문서에도 열린 항목으로 적혀 있지 않다.
- **선택지**
  - (가) 지금처럼 기록만 한다.
  - (나) 끝 신호를 받으면 드레인 뒤 회차를 끝낸다.
  - (다) 끝 신호 뒤 정해진 시간 동안 활동이 없을 때만 끝낸다.
- **추천**: (가).
- **근거**
  - (가)에서는 끝 신호의 진위가 결과에 영향을 주지 않는다. 신호가 틀려도 러너 상한까지 그대로 본다.
  - (나)·(다)는 비용을 줄이지만, 신호가 틀린 쪽(B 또는 O)의 회차만 짧아진다.
  - 재실행 파일럿에서 B 엔진은 봉인 뒤에도 모델 66번·대상 12번을 시도했다(결정안 §8). 활동이 끝났다고 보기 어려운 기록이다.
- **파일럿 뒤 결정**: 끝 신호 뒤 남는 시간의 비용이 크면 (다)를 다시 본다.

## 5. 모델 목록 16KiB(`MaxSelectedDataBytes`)

- **지금 상태**: "측정 근거로 다시 정한다"가 공식 측정 고정 전 필수 항목이다(개발 계획). 지금 값은 공개 목록 상한이 64개이던 때 기준이다. 공개 목록은 이제 48KiB 바이트 절단이고 개수 상한은 256이다. 시험상 100바이트 경로 98개 중 92행만 들어간다. 프로세스 안 통합 시험(#670)은 공개 99·모델 91행·모델 목록에서 빠짐 8을 보였다.
- **선택지**
  - (가) 16KiB를 유지한다.
  - (나) 공개 목록 전부가 들어가게 올린다(공개 투영 48KiB에 맞춤).
  - (다) 모델 입력 토큰 예산에서 거꾸로 정한다.
- **추천**: (나). 단, 아래 근거의 측정을 먼저 한다.
- **근거**
  - 공개 목록은 이미 바이트로 묶여 있다. 고른 끝점을 모델 목록에서 또 빼면 모델이 승인 범위 안 끝점을 모른 채 돈다. 탐색 성능을 깎는 통제는 줄인다는 기조와 맞지 않는다.
  - 대신 Planner·Worker 호출마다 입력이 늘어난다. 이 증가량은 유료 호출 없이 합성 fixture로 바이트·토큰 수만 잴 수 있다.
- **지금 결정 가능**: (나)로 정하고, 합성 측정으로 입력 증가량만 확인한다.

## 6. 경계 원자료 바이트 상한(`evidence_max_bytes`)

- **지금 상태**: 회차 정책이 정하고 코드 기본값은 없다([탐색 경계 계약](../contracts/exploration-boundary.md) §4.1). 상한에 닿은 회차는 `UNDECIDABLE / boundary_export_truncated`다([서명된 보존 원자료](preservation-signed-runs.md)). 러너 설정은 1GiB까지 받는다. 공식 값은 없다.
- **선택지**
  - (가) 러너 상한 근처의 큰 고정값.
  - (나) 파일럿 실측 최대 크기에 여유 배수를 곱한 값.
  - (다) 요청 예산 × 행 최대 크기로 계산한 값.
- **추천**: (나).
- **근거**
  - (다)는 차단 행이 요청 예산에 묶이지 않아(차단 요청은 전달 수에 들어가지 않음) 상한을 보장하지 못한다.
  - (가)는 잘림을 거의 없애지만 디스크를 크게 잡는다.
  - 잘린 회차는 판정이 UNDECIDABLE이 될 뿐 무효가 아니다. 그래서 너무 작으면 보존 판정 수가 줄어든다.
- **파일럿 뒤 결정**: 값과 여유 배수. 공식 예산 파일럿에서 원자료 크기를 잰다.

## 7. Juice Shop 집계 기준 경로

- **지금 상태**: 발견 비교는 경로 틀 커버리지로 한다. 방향은 B·O가 실제로 닿은 경로 틀의 합집합이 기본이고, Juice Shop 소스의 라우트 목록은 회차 뒤 보조 지표로만 쓴다(개발 계획, 2026-11-17 결정). VAmPI 3차 회차에서 명세 기준으로 발견 2→4, 진단 요청 2→7을 보였다.
- **남은 세부와 추천**
  - **합집합 범위**: 같은 세션의 B·O 모든 유효 회차.
  - **틀 단위**: (메서드, 경로 틀). 값처럼 보이는 조각은 `{id}`로 가린다. HEAD는 GET으로 본다.
  - **B·O를 같은 기준으로 세는 법**: B에는 E②가 없어 "진단 요청"을 따로 가를 수 없다. 공식 비교는 계측기가 센 전달 요청(O는 본 입구와 탐색 입구 합)의 경로 틀로 한다. O의 탐색·진단 구분 지표는 O 안의 보조 지표로 따로 싣는다.
  - **분모가 결과에 따라 달라지는 점**: 합집합은 결과에서 나온 분모라서, 같은 세션 회차를 더 돌리면 분모가 바뀐다. 그래서 보고에는 분모 크기를 같이 싣는다.
- **지금 결정 가능**: 위 세부.

## 8. 브라우저 MCP 노출 차이(O 21·B 0)와 MCP 끈 회차

- **지금 상태**: O의 탐색 단계는 허용 목록 브라우저 MCP 21개를 쓰고, B는 0개다(원본은 브라우저 MCP를 꺼진 채 시드한다). #678이 "선언된 차이로 둘지, MCP 끈 O를 따로 돌려 통제 비용을 분리할지"를 프로토콜 고정 때 정할 항목으로 올렸다. 제품 3차 회차(VAmPI)에서 공개 끝점 6개 중 3개의 출처가 브라우저 이동이었다.
- **선택지**
  - (가) 선언된 차이로 두고 O만 돈다.
  - (나) MCP 끈 O(`O-nomcp`)를 같은 세션에 추가로 돈다. 그러면 B·O 차이 안에서 MCP 효과를 따로 뗄 수 있다.
  - (다) B에서 MCP를 켠다.
- **추천**: (가)로 시작하고, (나)는 파일럿 뒤에 정한다. (다)는 택하지 않는다.
- **근거**
  - (다)는 원본 설정을 바꾸는 것이라 "원본 그대로"인 기준선이 깨진다.
  - (나)는 회차 수를 1.5배로 늘린다.
  - 보존율 결론("O가 원본 능력을 보존했다")에 MCP 효과가 섞이는지는 O 회차의 MCP 출처 비중을 보면 판단할 수 있다.
- **파일럿 뒤 결정**: O 파일럿에서 MCP 출처 발견의 비중을 보고 (나) 여부를 정한다. #678의 B 전용 CLI 확인(파일럿 B 3회)과 같은 시점이다.

## 9. OPTIONS 거부

- **지금 상태**: 등록 메서드는 제품 최대 5개이고, DELETE·OPTIONS 거부는 O 통제 비용으로 사유별로 기록한다(결정안 §3). "OPTIONS 거부가 눈에 띄면 읽기 계열 허용을 따로 올린다"는 조건부로 열려 있다. 공식 프로파일과의 불일치는 §0에 있다.
- **선택지**
  - (가) 지금대로 기록만 한다.
  - (나) OPTIONS를 읽기 계열로 제품 허용에 넣는다(동찬님 항목, 통제 경계 변경).
  - (다) B에서도 OPTIONS·DELETE를 막는다(공통 조건).
- **추천**: (가).
- **근거**
  - (다)는 원본 동작을 바꾸므로 원본 보존 비교의 기준선이 달라진다.
  - (나)는 E② 허용 범위를 넓히는 결정이라, 실제로 거부가 결과에 영향을 줬다는 근거가 있을 때 올린다.
- **파일럿 뒤 결정**: O 파일럿의 OPTIONS 거부 수와, 그 경로가 B에서 발견·진단에 쓰였는지를 보고 (나)를 올릴지 정한다.

- **지금 상태**
  - 평가 프로토콜 §5.1은 시범 1200초·400건이고, 예산은 한 번만 조정한다.
  - 분리 배치의 공통 예산은 계측기 기준 두 입구 합이다(결정안 §3).
  - O 제품 상한은 기본값이다(회차 대상 요청 400, 실행 1800초).
  - O 모델 예산 값은 기록 방식만 정했고(결정안 §3.3) 공식 값이 없다.
- **추천**
  - **러너 상한이 먼저 걸리게 둔다**: 공통 요청 예산 R ≤ 제품 대상 요청 상한, 시간 예산 < 제품 실행 1800초.
    - 계측기 전달 수는 O의 E② 쪽 도착과 탐색 쪽 도착을 합한 값이다.
    - 제품 E② 예산은 정책 검사를 통과해 보내려고 예약한 요청을 센다(`e2proxy/execution.go`의 `Ledger.Reserve`). 연결에 실패해 대상에 도착하지 못한 요청도 여기에 들어간다.
    - 그래서 R을 제품 상한과 같게 두면 E② 상한이 먼저 걸리는 경우는 하나뿐이다: 연결 실패 수가 탐색 쪽 도착 수보다 많을 때.
    - 그렇게 걸리면 `product_limit`로 남고 통제 비용이 된다.
  - **O 모델 예산은 러너 상한보다 늦게 걸릴 값으로 둔다**: 모델 예산이 먼저 걸리면 O만 일찍 멈춰 비교가 기울기 때문이다.
- **파일럿 뒤 결정**: 1200초·400건의 한 번 조정(평가 프로토콜 규칙 그대로)과 O 모델 예산 값. 파일럿 기록으로 회차당 비용을 보고 정한다.

## 11. 라운드 순서·반복 수

- **지금 상태**: 조건당 유효 회차 N ≥ 3, `B O O B B O`, 무효 재실행도 교대 순서 유지(평가 프로토콜 §5.1). N=5로 올릴지는 시범 비용을 보고 정한다. `B O O′ | O′ O B | B O O′`는 수용시험(R-F·R-R) 순서이고 공식 비교 순서가 아니다.
- **추천**: N=3, `B O O B B O`. §8에서 (나)를 택하면 세 칸 묶음 교대(`B O X | X O B | B O X`, X = `O-nomcp`)로 바꾼다.
- **파일럿 뒤 결정**: N=5 여부. 회차당 비용과 B↔B 퍼짐(§12)을 보고 정한다.

## 12. B↔B 잡음 기준

- **지금 상태**: 같은 묶음 원본 회차끼리의 보존율을 순서쌍마다 계산해 평균·SD를 참고값으로 싣고, 판정에는 쓰지 않는다([브라우저 수용시험](browser-acceptance.md)). 공식 비교(B 대 O)의 해석 기준으로 쓸지는 정하지 않았다.
- **선택지**
  - (가) 참고값으로만 싣는다.
  - (나) 보고 규칙으로 쓴다. O와 B의 차이가 B↔B 퍼짐 안이면 "차이를 주장하지 않음"으로 적는다.
  - (다) 통과선에 넣는다.
- **추천**: (나). 통과선은 바꾸지 않는다.
- **근거**: 원본끼리도 회차마다 결과가 다르다. 그 폭 안의 차이를 개선이나 손실로 적으면 과장이 된다. (다)는 결과를 보기 전에 정한 통과선을 바꾸는 것이라 하지 않는다.
- **지금 결정 가능**: 보고 규칙. 퍼짐 값은 공식 회차에서 나온다.
