# E② 등록 HTTP 조회 전송기

상태: `transmit/`의 독립 Go 구현과 합성 HTTP 시험. ARTEX 실행 도구·GUARD/Interceptor·DB 감사·실 KG/인증 어댑터 연결은 후속이다. 기존 [검증기 seam](./idor-verifier-seam.md)의 `idor.Transmitter`를 구현하며 기존 검증기·비교기는 변경하지 않는다.

## 입력과 실행 허가

`NewHTTP(ctx, Config)`는 서버가 만든 **한 실행·작업·검사·reset 세대·집행 정책**의 불변 사본을 만든다. LLM 출력으로 Config를 만들거나 등록을 확장하면 안 된다. 서버 어댑터가 다음 값을 검증해서 제공해야 한다.

- `Scope`, 집행 정책 만료, 요청 예산·최소 간격·제한 시간·응답 최대 바이트.
- 대상 origin 하나와 운영자가 확인한 연결 IP 하나. DNS 조회 없이 해당 IP/대상 포트에 연결하며 URL의 Host/TLS 인증서 호스트 검증은 유지한다. DNS 승인·IP 선정은 이 패키지 밖의 책임이다.
- 자원 ref → 정확한 URL·조회 허가 ref·`ReadOnly`·검사에 사용할 계정 목록. GET도 상태를 바꿀 수 있으므로 `ReadOnly=true`를 별도로 등록해야 한다.
- 인증 어댑터가 실제 신원을 확인한 계정 label·불투명 세션 handle·상태·만료·비공개 HTTP 헤더. 같은 handle의 중복 등록을 거부한다. 서로 다른 handle도 같은 사용자의 세션일 수 있으므로 label은 인증 어댑터가 확인한 서로 다른 신원을 나타내야 한다. 이 패키지가 로그인이나 세션의 실제 유효성을 확인하는 것은 아니다.
- 승인된 비민감 시험 표식과 선택적인 응답 모양 규칙. 임의 대상에 대한 범용 정상 응답 판별기가 아니다.

실행 허가와 앱 기대권한은 별개다. `Resource.Accounts`는 B 계정으로 교차 조회 **시험을 수행할 허가**다. KG의 `ExpectedAccess=deny`는 판정 입력이며 이 목록을 대체하지 않는다. 서버는 `idor.Candidate`도 같은 신원 사본에서 만들어야 한다. 기존 `Verify`는 후보의 상태를 오라클에 전달하므로 전송기 단독으로 후보/판정 저장의 출처까지 보증하지 않는다.

통합 판정에는 `tx.VerifyRead(candidate, kg)`를 사용한다. 후보의 서로 다른 등록 신원과 실행 허가를 확인하고, KG의 정책·표식을 한 번만 조회해 사본을 고정한다. 표식의 `(Field, Value, Trivial)` 집합이 전송기의 불변 등록값과 정확히 일치해야 하며 순서만 다른 것은 허용한다. 불일치·중복·미등록은 송신 전에 `UNDECIDABLE`과 안전한 사유로 반환한다. 이후 `idor.VerifyRead`에 이 고정 resolver를 전달해 setup POST 없이 owner GET·cross GET만 제안하고 재조회에 따른 변경을 차단한다. 전송 계층 `Send`를 독립 KG와 직접 조합하거나 `idor.VerifyRead(candidate, tx, kg)`를 곧바로 호출하면 기존 비교기의 부분문자열 매칭 때문에 이 바인딩을 우회하므로 통합 확정 판정 경로로 사용하면 안 된다. preflight 거부는 HTTP 시도 자체를 만들지 않으며 호출자가 반환 사유를 검사 기록에 보존해야 한다.

## 전송과 중지

`Send`는 기존 인터페이스이며 `SendDetailed`는 `(Capture, Receipt, ok)`를 추가 제공한다. 제안의 URL·헤더·본문을 받지 않는다. `Inputs`는 반사 검사용 값이며 네트워크에 추가하지 않는다.

1. 정확한 GET, `StateChanging=false`, 등록 자원·조회 허가·계정·handle/신원 상태·만료를 검사한다. POST를 포함한 다른 동작은 모두 거부한다. 표식은 별도 승인된 fixture에서 미리 준비하며 `tx.VerifyRead`는 setup을 제안하지 않는다. 기존 `idor.Verify`를 별도로 호출하면 setup POST는 여전히 거부되고 그 `result` 감사 기록도 필수다. 이 기록이 실패하면 이후 admission이 닫힌다.
2. 한 번에 하나씩, 취소 가능한 간격 대기를 거친다. 감사 sink의 intent 기록 성공 뒤 **송신 직전** 중지·만료·계정·예산을 다시 확인하고 예산을 예약한다. 거부된 요청은 예산을 소비하지 않으며 전송 실패한 예약은 환불하지 않는다.
3. 직접 소유한 HTTP/1 전송기를 사용한다. 환경 프록시, 연결 재사용, 자동 압축, 리다이렉트 후속 전송, 애플리케이션 재시도를 사용하지 않는다. 고정 IP 연결 지점에서도 대상 authority와 중지를 재확인한다. HTTPS 인증서 검증을 끄지 않는다.
4. 헤더/본문 읽기 전체에 제한 시간·만료를 적용한다. 본문은 최대값+1 바이트까지 읽어 초과를 거부하고 연결을 닫는다. 압축 응답은 지원하지 않는다. 응답 헤더는 Go 표준 전송기의 기본 상한을 따른다.

`Stop`은 새 admission을 닫고 대기·진행 중 context를 취소한다. 이미 admission된 요청의 전송이나 대상의 처리를 되돌리지 못한다. 새 정책·reset에는 새 인스턴스를 만든다. 이 API는 임의 셸/브라우저/MCP/기존 ARTEX 도구의 통신을 차단하지 않는다.

## 캡처와 감사

`ok=true`는 제한된 응답 캡처 완료이며 접근 성공·취약점 확정·안전의 의미가 아니다. HTTP 오류도 미분류 캡처가 될 수 있다. 송신 거부·timeout·리다이렉트·압축·크기 초과·감사 실패에는 `ok=false`다. 실패한 단계를 “취약점 없음”으로 매핑하지 않는다.

JSON 응답은 중복 키(이스케이프 별칭 포함)·후행 문서·잘못된 UTF-8·과도한 중첩을 거부한다. `JSONViewRule`의 상태 경로·데이터 객체·등록 필드 모양을 확인하고, **등록된 비민감 표식과 필드 값이 정확히 같을 때 그 표식만** `ResponseView.Body`로 전달한다. HTTP 200만으로 정상 판정하지 않는다. 등록 규칙 없음/모양 불명은 미분류다. 실제 URI(디코딩된 경로·쿼리 포함)·헤더·논리 입력에 들어 있던 표식은 반사 가능성이 있으므로 투영하지 않는다. 본문의 상태 값이 등록된 오류 값이면 오류 템플릿으로 표시한다. 단 HTTP 상태가 2xx가 아니면 등록 규칙과 무관하게 미분류로 두며 오류 템플릿 판정도 하지 않는다. 일반적인 공통 화면 판별은 지원하지 않으므로 등록 규칙은 자원별 시험 응답에 한정한다.

**민감 본문을 수신 전 차단하는 DLP는 아니다.** 응답 원문은 프로세스 안에서 크기를 제한해 읽고 파싱한다. 외부로 전달하는 캡처·감사·영수증에는 원문·URL·자격증명·원시 오류를 넣지 않는다. 실제 민감 자료를 조회하지 않는다는 보장은 시험 데이터·대상 설정에서 별도로 확보해야 한다.

`Recorder.Record`는 intent/result 이벤트를 받는다. 서버가 내구성 있는 저장·쓰기 권한 분리를 구현하고 context를 지켜야 한다. 임의 no-op 구현으로 감사 완료를 주장하면 안 된다. intent 실패는 송신을 막고, 결과 기록 실패는 이미 전송됐을 수 있으므로 `ok=false`로 반환하고 후속 admission을 막는다. 전송 전 mutex 안에서는 외부 recorder를 호출하지 않아 Stop을 방해하지 않는다.

`Receipt`에는 등록 계정/불투명 세션 참조·시도 번호·안전한 사유·admission 여부/시각·완전한 요청 쓰기 관찰·응답 수신 여부·HTTP 상태만 담는다. 감사 이벤트의 `At`은 실제 기록 호출 시각이다. `Admitted=true`는 송신 예약이며 실제 도달 증명이 아니다. `RequestWritten=false`도 부분 송신이 없었다는 증명이 아니다. `Attempt`는 이 인스턴스 내 순번이므로 외부 저장 키는 실행 범위와 함께 발급해야 한다. 변조 탐지 seal·판정 저장 게이트는 아직 이 구현 범위 밖이다.

## 검증

`go test -count=1 ./transmit ./idor ./oracle`과 `go test -race`에서 합성 대상의 실제 수신 건수, 중지 경합, 승인·예산·감사 실패, TLS/고정 IP, 리다이렉트·프록시·재시도, 표식 투영·민감 원문 제외, 기존 IDOR 오라클 연결을 검증한다. 실제 Juice Shop이나 baseline을 실행하는 시험은 아니다.
