# 정확 일치 경로 승인 — 제품 서버 계약

상태: 서버 구현·리뷰 대상. 대상 등록·승인 화면과 새 모드 파서는 이경준·윤재상 후속 작업이다. 서버 시험을 Workbench 전체 지원 완료로 표시하지 않는다.

## 입력과 저장

기존 `path_prefixes`의 `/users/v1`은 기존처럼 그 경로 및 하위 경로 조각 접두다. 새 `=/`는 **query 없는 `/` 한 경로**다. `=/a/`는 `/a/`만 허용하고 `/a`와 구별한다. 접두 `/`는 계속 전체 경로 접두이므로 정확 루트 승인에 사용하지 않는다. `=`를 떼서 접두로 저장하는 변환은 금지한다.

등록 예시(나머지 요청·수명 상한은 설치 정책을 따른다):

```json
{"url":"https://owned.example/","path_prefixes":["=/","/users/v1"],"methods":["GET","HEAD"],"readonly_basis":"승인 조직이 명시한 비변경성 근거 문장","requests":100,"valid_hours":4}
```

기존 대상 등록 API와 DNS 소유 증명·승인·revision·철회 API를 그대로 사용한다. 보호 저널·대상 응답·준비 scope·진단 흐름·탐색 grant에는 `=/` 표현 자체를 보존한다. 다른 origin·IP·메서드·예산을 승인하지 않는다. 잘못된 경로 표현(`=`, `==/`, query/fragment·percent escape·backslash·dot segment·중복 slash 등)은 등록을 거부한다. 등록 검증 오류는 기존 `invalid_path_scope`이며 HTTP/IPC의 형식 검증에서 거부되면 기존 잘못된 요청 오류다.

정확 경로의 query는 첫 범위에서 모두 거부한다(`?`도 포함). 위험 query를 분석해 자동 승인하지 않는다. 기존 prefix의 query 동작·위험 경로 검사·진단 흐름의 C23 검사는 유지한다. query가 필요한 경로는 별도 명시 승인 계약을 확장하기 전까지 exact로 보낼 수 없다.

## 실행 정책과 감사

제품 정책 파일은 `{"path_prefix":"/","path_match":"exact",...}`로 명시한다. `path_match` 생략은 기존 접두 동작이고, 칸이 있으면 `"exact"` 하나만 받는다. null·빈 문자열·미지원 모드를 접두 기본값으로 바꾸지 않는다. 인증 준비의 purpose 전용 정확 매칭과는 별개이고 함께 지정할 수 없다.

내용 지문은 exact에 `path_match: exact_path_no_query_v1`를 넣는다. 기존 prefix 정책의 정본·지문 벡터는 유지한다. 감사의 `rule_ref`는 회차의 보호 정책 파일과 내용 지문에 결속된 규칙을 가리킨다. 작업대 control-policy의 규칙에도 `path_match`를 제공하므로 감사 규칙을 정확/접두로 구별할 수 있다. 기존 E② 영수증 형식과 E③ 판정 입력은 바꾸지 않는다.

실행 factory·정책 문서 검증·실데이터 조회는 같은 모드를 보존한다. 이전 정책/실행에 정확 승인을 암묵적으로 추가하지 않는다. 신규 exact 정책은 이전 서버의 엄격한 정책 필드 검사에서 거부되고, 이전 대상 lookup은 `=/`를 `/` 접두로 해석하지 못한다. downgrade로 실행 권한을 넓히지 않는다.

## 화면 인계

- 대상 등록의 prefix/exact 선택을 분리하고 exact는 `=/`로 제출한다. 서버가 돌려준 표현을 승인 화면에도 그대로 구별해 보인다.
- control-policy 규칙의 선택 칸 `path_match?: "exact"`를 파서에 추가한다. 생략은 기존 prefix, 미지원 값은 불명/오류로 유지한다.
- exact는 query 없는 단일 경로, prefix `/`는 전체 하위 경로라는 차이를 표시한다.
- 기존 대상 목록/초안 조회에 새 의미가 등장하므로 화면 파서를 먼저 배포한 뒤 exact 등록 UI를 연다. 기존 prefix 대상의 응답은 바뀌지 않는다.
- 실제 Workbench 새로고침·등록·승인·시작 수용시험과 실제 Qwen 후속 회차는 이번 서버 시험에 포함되지 않는다(`NOT_RUN`).

검증: 실제 소유한 E② HTTP 수신 계측, 직접/브라우저 탐색 프록시의 TLS 수신 계측, 보호 대상 등록·승인 저널 재시작, 제품 준비 프로필/정책 생성, 정본 지문, 인코딩·메서드·origin·query·리다이렉트·철회 음성 대조를 사용한다. DNS/TLS 소유 증명 시험 대역은 별도 합성 의존성으로 명시하며 실제 인터넷 대상 소유 검증 결과로 계산하지 않는다.
