# 진단 후보 예상 심각도 계약

후보의 예상 심각도는 검토 우선순위 제안이다. E③ 확정 판정·송신 권한·CVSS 점수가 아니며, 새 모델 요청을 만들지 않는다.

## 입력과 저장

기존 `submit_diagnostic_candidate`에 선택 필드 `suggested_severity`, `severity_rationale`를 추가한다. 허용 등급은 `critical | high | medium | low | info`다. 표시 근거는 한국어가 포함된 한 줄로, DLP 후 공백을 정리해 최소 8자·최대 UTF-8 1,024바이트를 수용한다. 도구의 영문 설명에도 바이트 상한과 한국어 약 300자 이내 권장을 명시한다. JSON Schema의 `maxLength`(1,024자)는 글자 수이고 harness가 검사하지 않으므로 저장 바이트 상한을 대신하지 않는다. 가림·공백 정리 뒤 1,024바이트를 넘는 근거는 글자 경계에서 잘라 끝에 `…(이하 생략)`을 붙여 상한 안에 저장한다(가린 뒤에 자르므로 경계에 걸친 비밀 조각이 남지 않는다). 가림 전 입력이 4,096바이트(1,024자 × 4바이트)를 넘으면 평가만 생략한다. 이 하한은 빈 문장·짧은 등급 반복을 거르는 형식 조건이며, 설명한 영향의 사실 여부를 자동 검증했다는 뜻은 아니다. 모델 지시는 유형명만으로 추정하거나 CVSS를 만들지 않도록 한다.

다음 조건을 모두 만족해야 평가를 보존한다.

- 기존 task/intent/run/call·증거 버전·digest 검증 통과
- 실제 E② 호출의 `completed` 관찰, 호출·Bash·프로세스·프록시 마감 및 감사 완결
- 실제 전송·응답 수가 있고 불명 수가 0
- 순번·시도 참조·시각이 있는 허용 HTTP 응답 관찰, 응답 완료·감사 완결
- 출력 및 관찰이 잘리지 않았고, 관련 호출도 같은 조건을 만족함

서버는 `severity_source=worker_estimate`를 고정한다. 모델은 출처·판정·증거 원문을 지정할 수 없다. 알려진 실행 비밀을 포함한 기존 실행 DLP와 문자열 DLP를 근거 설명에도 적용한다. 문자열 enum 오류·누락·잘못된 선택 필드 타입·근거 부족은 **평가만 생략**하고 유효한 후보는 계속 저장한다. 기존 핵심 입력·증거 위반까지 수용하는 것은 아니다.

`DiagnosticCandidate`의 선택 JSON 필드로 저장한다. `diagnostic_candidate_v1`과 기존 fact 저장소를 유지하므로 SQL 마이그레이션은 없다. 이전 기록은 새 필드가 없어도 읽으며 미평가다. 새 reader는 평가 메타데이터를 정규화하지만 기존 증거 검증은 완화하지 않는다. 이전 reader는 선택 필드를 무시할 수 있고 기존 원본은 보존된다.

동일 call·유형·이름·증거의 재제출은 기존 ID를 반환한다. 등급만 바꾸거나 이전 기록에 등급을 추가해 덮어쓰지 않는다. 평가로 finding·E③ verdict를 생성하지 않으며 `verification=manual_review_required`, 후보의 `outcome=review`를 유지한다.

## 지문과 조치 자료

`EvidenceDigest`는 기존 관찰만의 지문이므로 평가 필드가 바뀌어도 변하지 않는다. 기존 조치 `SourceDigest`는 저장 JSON 전체를 해시하므로 평가 메타데이터가 바뀌면 달라지고 이전 조치 자료는 stale이다. 이 계약을 우회하려고 새 필드를 원본 지문에서 제외하거나 기존 저장본을 자동 수정하지 않는다.

## 보고서·공개 범위

내부 remediation API의 `severity`에 유효한 예상 등급을 전달하고, 선택 필드 `severity_source`, `severity_rationale`를 함께 제공한다. 기존 필드만 있는 응답도 수용한다. UI·HTML·DOCX에서 후보는 **예상 높음 · 검토 필요**, 확정 finding은 **높음**, 미실행·불명·등급 없는 항목은 **위험도 미평가**로 표시한다. `info`는 **정보성**이다. 모르는 값을 낮음·정보성으로 대체하지 않는다.

`SourceLoadFailed`, 훼손, 불명, 미실행, 잘림 및 평가 근거 부족은 미평가다. 확정 심각도 분포는 E③ 증거로 확정된 finding만 센다. 후보 예상 분포는 별도 문구로 표시하고 목록 필터는 실제 서버 평가를 사용한다.

공유 API에는 새 평가 출처·근거를 내보내지 않고 심각도는 기존 미평가 정책을 유지한다. 공유 HTML·DOCX에서도 후보 평가와 근거를 제거한다. 기존 공유용의 확정 finding 등급 공개 정책은 바꾸지 않는다. 새 필드로 자유문장·원문 비밀·추정 등급의 공개 범위를 확대하지 않는다.

## E③ 저장 경계

`e3record.Source.Severity`는 기존 검증 경로에서 검사되며 `db/e3_findings.go`의 확정 finding 삽입 시 findings와 finding 노드에 저장된다. 보고서는 기존 finding의 저장 등급을 그대로 사용한다. finding에 연결되지 않은 issuance/manifest/verdict의 조회에는 재사용할 독립 심각도 필드가 없다. 따라서 IDOR라는 유형명으로 새 등급을 만들지 않으며 미평가를 유지한다. `allowed` verdict는 비취약 판정이고 위험도 분포에 포함하지 않는다.

이번 변경은 E③의 불변 저장 스키마·오라클·manifest·증거 결속·확정 조건을 변경하지 않는다.

## 화면 통합

기준은 최신 dev이며 #661의 진행 게이지·실시간 후보 목록·범위 시작 제어는 구현하지 않거나 덮어쓰지 않는다. `UrlLiveLive.tsx` 변경은 심각도·보고서 표시 부분이다. 정보성 딱지는 기존 밝은·어두운 테마의 강조색 토큰을 쓰는 `.sev.info`로 미평가와 구분한다. 표시 어휘·API 파서·대시보드 집계는 UI 담당자 리뷰 대상이다.

#661과 통합할 때는 우선 조치·빈 계정 비교 표 제거를 유지하고, 예상 심각도 근거와 `entrySeverity` 기반 확정·예상 분리 집계를 보존한다. 공통 `SEV_KEYS`에 `info`를 남겨 실시간 목록에서도 정보성 후보가 누락되지 않게 한다. 실시간 목록은 검증 전 엔진 값이므로 `entrySeverity`를 적용하지 않고 기존 안내를 유지한다. 별도 임시 통합 검증은 팀원 브랜치의 병합·수정을 뜻하지 않는다.
