# 일반 HTTP 프록시의 원문 보존·자격 처리 지원 범위

상태: **구현 검토 초안·운영 비활성.** #216의 요청·응답 전달 충실성 피드백을 반영한
최소 지원 범위와 보호 세션 후보 모드를 정리한다. 이 문서가 팀 계약 채택, 실제 승인,
정책 지문 발급 또는 공식 평가 수용을 뜻하지 않는다.

기준은 [E② 공통 계약](./e2-network-enforcement.md)의 §3 일반 모드와 §7.1,
[프록시 통제 결정](../e2-proxy-control-decision-draft.md)의 §5.2·§10이다.
기존 등록 GET 계약·감사 v1·E③ 증거 의미는 넓히지 않는다.

## 기본 모드: 원문을 바꿔 성공으로 만들지 않음

`Config.HeaderMode`의 기본값은 `preserve`다. 허용되는 형식 변환·hop-by-hop 정리와
프로그램이 발급하는 시도 ID 외에는 원 요청의 의미를 조용히 바꾸지 않는다.
Host와 path/query 원문, 메서드, body 및 end-to-end 헤더를 보존한다.

- 호출자가 `Authorization` 또는 `Cookie`를 보냈으면 대소문자·빈 값 여부와 무관하게
  예약·대상 송신 전에 `unsupported`로 기록하고 계수한다. 삭제 후 익명 요청으로
  보내지 않는다. 이 단계는 모델이 받은 자격값으로 로그인하는 기능을 지원하지 않는다.
- 일반 `Rule.Headers`는 요청에 이미 있는 값의 정확한 제약이다. 값을 추가하거나 덮지
  않는다. 누락·값 불일치 또는 hop 정리 후 유지할 수 없는 제약은 송신 전에 거부한다.
- `Accept-Encoding`은 미지정 또는 명시적 `identity`만 지원한다. 다른 협상값을 지우고
  보내지 않는다. 지원하지 않는 협상은 예약 전에 거부한다.
- `User-Agent` 부재에 기본값을 넣지 않는다. 빈 값·빈 POST framing처럼 전송 계층이
  바꾸기 쉬운 사례도 실제 wire 시험으로 보존 또는 송신 전 미지원 처리를 확인한다.
- 무리다이렉트·무자동 재시도, 최종 목적지·대상 TLS 검증과 현재 승인·예산 검사는
  그대로 적용한다. 공개 시도 ID나 모드 문자열은 실행 자격이 아니다.

기본 모드에서 명시 비밀 헤더가 설정되면 초기화를 거부한다. 따라서 기존 설정이
실수로 보호 세션 주입 모드를 활성화하지 않는다.

## 헤더 분류와 보호 세션 후보

일반 헤더 값 전체를 비밀 목록으로 취급하지 않는다. 예를 들어 정책의
`Accept: application/json`이나 `Accept-Encoding: identity` 때문에 공개 응답의
같은 문자열이 바뀌어서는 안 된다.

| 입력 | 의미 | 허용되는 사용 |
| --- | --- | --- |
| `Rule.Headers` | 비밀이 아닌 정확한 요청 헤더 제약 | 값 비교만 수행하며 주입·덮기 없음 |
| `Rule.CredentialHeaders` | 신뢰 host가 명시한 보호 자격 헤더 | 후보 모드에서만 사용, 값은 JSON·뷰·LLM에 노출하지 않음 |

명칭은 대소문자를 무시해 중복·두 분류의 충돌을 거부한다. 비밀 헤더 입력으로
Host, 시도 ID, proxy/hop-by-hop, framing 또는 인코딩 협상 제한을 우회할 수 없다.
`Authorization`·`Cookie`를 일반 헤더로 선언해 자격 분류를 피하지도 못한다.
사용자 정의 자격 헤더의 비밀 분류는 신뢰 host의 명시 선언 책임이다.
송신 때 제거되는 앞뒤 공백·탭이 있는 자격값은 초기화에서 거부한다. Cookie는 원문을
전달하되 표준 파서가 따옴표를 해제한 실제 값도 반사 검사에 포함한다.

명시적 `protected_session_proposal`은 **별도 검토 중인 후보 모드**다.
신뢰 host가 준비한 계정·세션의 자격 헤더만 넣으며, 호출자가 같은 헤더 이름을 보내면
그 값을 비교해 허용하거나 덮지 않고 송신 전에 거부한다. 호출자 입력이 사용할 계정,
세션 또는 권한을 선택하지 못한다. 모드는 실행 중 바뀌지 않고 실행·정책 뷰에 표시한다.

이 후보 모드는 현재 공통 계약의 공식 일반 HTTP 모드로 채택된 것이 아니다.
실제 주입 결정·서버 활성 조건·정책 정본과 지문·평가에서 선언한 차이가 먼저
합의·동결돼야 한다. `PolicyRevision` 문자열이나 뷰의 모드 값만으로 그 근거를
대체하지 않는다. 현재 구현을 기본 서버나 공식 회차에 자동 설치하지 않는다.

## 응답: 원문 전달 또는 명시적인 불명

안전하게 지원할 수 있는 응답은 end-to-end 헤더와 body를 원문대로 전달한다.
일부 값을 삭제하거나 `[REDACTED]`로 치환한 응답을 정상 대상 응답처럼 내보내지 않는다.

다음 응답은 이번 단계에서 원문 전달을 지원하지 않는다.

- `Set-Cookie`, `WWW-Authenticate`, `Authentication-Info` 등 자격 관련 고정 헤더가
  있는 응답. 새 자격값도 모델 입력으로 보내지 않는다.
- 명시 비밀 헤더나 보호 자격값이 status·헤더·trailer·body에 나타나는 응답.
- 지원하지 않는 인코딩, 제한을 넘거나 완전히 수신하지 못한 응답.

대상 송신이 일어났다면 허용 결정과 송신·응답 관측을 유지하고 `unknown`으로 남긴다.
원 응답의 헤더·본문은 도구에 공개하지 않는다. 이를 미송신 정책 거부, 대상의
접근통제 성공, 취약점 없음 또는 재시도 허가로 바꾸지 않는다.
비밀 검사는 명시된 값과 자격 형태에 대한 제한된 검사이며 임의 인코딩의 보편적
DLP나 인증 정보 자동 발견을 보장하지 않는다.

## 현재 보류와 Unknown 한도의 연동 — 미해결 계약 차이

현재 코어는 자격 응답의 body·헤더를 보류할 때, 전부 수신했더라도
`ResponseReceived=true`·`ResponseComplete=true`와 `Reason=unknown`을 함께 남긴다.
이 보류도 `Counts.Unknown`과 `Limits.MaxUnknown`에 누적한다. 따라서 매 응답에
Set-Cookie를 붙이는 앱에서 MaxUnknown=3이면 HTTP 200 응답 세 개를 모두 수신한 뒤에도
실행이 unknown_limit으로 멈추며 네 번째 요청은 보내지 않는다. 보류된 본문이
없다는 사실을 불완전한 수신이나 대상의 접근통제 성공으로 해석하면 안 된다.

이는 공통 계약 §7.1의 response_received 축과 같은 분류가 아니며, 공식 비교 전에
선언해야 할 현재 구현 차이다. caller 로그인 자격 미지원·identity 전용 협상과 함께
정책 정본/지문 및 평가 조건에 동결해야 한다. 이 문서에 적었다는 이유로 정식
일반 모드 계약의 충족이나 평가 수용이 완료된 것은 아니다.

후속 제안은 응답 수신·표현 보류·전송 결과 불명을 분리하고, 보류 전용 사유/계수와
Unknown 중지 한도의 관계를 합의하는 것이다. 아직 채택하지 않았으며 현재 이유 enum,
정책 지문·export/채점 형식을 이 초안이 임의로 바꾸지 않는다. Ready는 문서 검토
요청 상태일 뿐이다. 공식 비교에서의 세 차이 처리 방향은
[#240](https://github.com/ABC2LAB/ABCDEF2LAB/pull/240)에 합의안으로 정리됐으나,
그 변경의 프로토콜 §2 반영·병합과 필요한 리뷰가 완료되기 전에는 이 PR을
병합하지 않는다. 원문 통과 모드 구현·정책 지문 반영·공식 회차 수용은 별도 검증이다.

## 회귀·수용 기준

| 사례 | 필요한 실제 결과 |
| --- | --- |
| 일반 HTTP·검사 HTTPS 양성 | 대상 수신과 원 Host/path/query/body·안전 응답의 바이트 보존 |
| caller 자격 헤더·정책 제약 충돌 | 대상 수신 0, 예약 미소모, 고정 사유·계수 |
| 일반 Accept·identity 문자열 | 공개 본문과 헤더의 같은 문자열이 바뀌지 않음 |
| 자격값 반사·인증 응답 헤더 | 원문 비공개, 허용/송신 관측 유지, 결과 불명 |
| 일반/비밀 입력 혼동·설정 원본 변조 | 초기화 거부 또는 분리된 불변 사본 사용 |
| 후보 모드 | 기본 비활성, 실행·정책 뷰 표시, 기존 승인·공유 예산 유지 |

실제 Linux/소유 대상·결정적 모델 대역 시험과 실제 모델·Docker·운영 권위 수용은
구분한다. #212의 `a5cb16b`는 관리자 소유 CI user namespace 지원 이후
[CI 42023365261](https://github.com/ABC2LAB/ABCDEF2LAB/actions/runs/42023365261)에서
46패키지 4,710 PASS·0 FAIL·2 SKIP이었다. 이전 상속 FD `Fstat` 실패는 과거 결과로
보존한다. 이 결과가 #219·#220의 새 의존 통합 커밋 검증이나 운영 수용을 대신하지 않는다.

정규화·한도 사유 분리, control 종료 사건, 공유 시도 순번, 정책 지문 정본, 공식
평가의 선언 차이 및 제품 export 어휘 정렬은 별도 후속이다. 평가 러너·계측기·채점기
파일을 이 변경에서 수정하지 않는다. 일반 E②와 기존 IDOR/E③의 동일 실행 조립,
실제 공급부와 첫 실제 통합 진단은 여전히 별도 수용이 필요하다.
