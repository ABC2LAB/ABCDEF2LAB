# 회차별 대상 승인 권한 모델 제안

상태: **#353에서 분리한 후속 구현 제안, 팀 합의·담당자 승인 전**(2026-11-10).
기존 설치 시 대상 origin 고정과 별개로, 로그인한 운영자가 대상 소유와 읽기 전용 진단 권한을 확인해 회차별 범위를 등록하는 정책 변경이다. 이 문서나 시험 성공을 팀 규칙 개정·공개 사이트 진단 승인으로 간주하지 않는다. 검토·합의 전 기본 실행 규칙의 대상을 확대하지 않는다.

## 변경 범위와 담당자 결정

| 항목 | 기존 #353 | 후속 제안 |
|---|---|---|
| 대상 권위 | 설치자가 고정한 origin/IP/path | 설치 상한 안에서 운영자가 DNS 소유 증명·범위를 등록하고 승인 |
| 설치 형식 | v1 고정 대상 | v2 대상 정책과 모델 정책 분리, 기존 v1 자동 이관 없음 |
| 최종 집행 | 기존 E②·보호 준비 서비스 | 동일 경로에 회차별 origin/IP/port/path/method/TLS SPKI·만료 결속 |
| 합의 필요 | Workbench/UI 삭제·설치 승인 | 새 대상 승인 권한 모델, 허용 네트워크/포트, TLS 사전 접촉·감사 |

단일 관리자 로그인 이름은 ABC2LAB이고 내부 승인 주체 ARTEX는 유지한다. DNS 소유만으로 모든 검사를 허용하지 않는다. 운영자에게 실제 진단 권한이 있어야 하며 GET/HEAD 경로의 비변경 근거·요청 상한을 함께 등록한다. 추가 권한 역할·제공자·쓰기 검사·IP literal 소유 증명은 별도 범위다.

최민준은 권한·보안·설치 경계를, 윤재상은 대상 승인 Workbench를, 이경준은 공용 계약·화면 접점을 검토한다. 사용자 제품 요구를 이들의 동의로 대신하지 않는다. #353의 UI 삭제 동의와도 별개로 검토한다.

## 허용과 거부

- 등록은 pending과 무작위 TXT challenge만 만든다. 로그인·URL·체크박스만으로 실행 권위를 만들지 않는다.
- DNS 소유 확인은 30분 내에 수행한다. 승인 요청의 valid_hours는 1~24시간이며 UI 기본값은 4시간이다. UI 요청 상한 기본값은 4이고 설치 상한을 넘지 않는다.
- 모든 해석 주소를 검사한다. 메타데이터·보호 서비스·loopback/link-local은 거부하고 사설 주소는 설치자가 별도로 승인한 좁은 CIDR만 허용한다. 보호 서비스 검사기가 누락되면 승인·시작을 거부한다.
- IP literal은 `dns_ownership_required`로 등록 단계에서 거부한다. TXT 실패라는 다른 가드에 의존하지 않는다.
- 시작 직전 TXT·DNS 주소 집합·선택 IP의 TLS SPKI·만료·철회를 재검증한다. 실제 대상 전송은 승인된 ConnectIP로 고정하며 기존 체인 검증 뒤에 SPKI를 추가 검사한다. 리다이렉트·다른 대상의 승인 재사용은 허용하지 않는다.

## 만료와 실행 중 처리

승인 ExpiresAt은 승인 시각+valid_hours와 검증한 인증서 NotAfter 중 빠른 값이다. 파생 회차의 정책 기한은 모델/설치 기한과 대상 승인 기한을 넘지 않는다. 만료 직전은 허용하되 **만료 시각과 그 이후**는 거부한다. TLS 확인 중 인증서가 만료되면 승인을 기록하지 않는다.

- lookup은 만료 승인으로 새 회차 자료를 만들지 않는다.
- current와 시작 recheck도 만료를 거부한다. 만료 뒤에는 DNS·TLS 재접촉 전에 실패한다.
- 실행 중에는 기존 준비/실행 검사와 250ms 주기의 current 감시가 context 취소를 요청하며, E②는 회차 정책의 기한을 신규 전송마다 집행한다. 이미 전송 중인 바이트의 취소·복구를 보장하는 의미는 아니다. 불명 결과·예약 비용 처리는 기존 계약을 따른다.
- 과거 보고서용 승인 참조는 보존한다. 만료·철회가 과거 결과를 새 권위로 바꾸거나 다른 대상의 범위를 수정하지 않는다. 새 실행에는 새 승인 절차가 필요하다.

## 시작 전 실제 접촉과 감사

초안·범위 조회가 무접촉이라는 설명과 **대상 승인·시작 사전 검사**를 구분한다.

| 단계 | DNS/TXT | 대상 TLS 접촉 | 대상 HTTP·모델 completion |
|---|---|---|---|
| 대상 등록·초안·범위 조회 | 없음 | 없음 | 없음 |
| 소유 확인 후 승인 | 조회 | 정상 경로 1회. 실패한 후보 IP가 있으면 주소별 1회, 최대 8회 시도 | 없음 |
| 명시적 시작 직전 재검증 | 재조회 | 승인된 선택 IP로 1회 | 이 검사 자체는 없음 |
| 승인된 진단 실행 | ConnectIP 고정 | 기존 E② TLS 경로 | 승인된 경로·예산 안에서만 수행 |

사전 TLS 검사는 HTTP 바깥에서 대상에 직접 연결하므로 E② HTTP 전송 카운터에 합산하지 않는다. UI도 이 접촉을 승인·시작 전에 안내한다. 시작 전 대상 HTTP 0은 **대상과 통신이 전혀 없다는 뜻이 아니다.**

별도 보호 저널 `state/targets/tls-contacts`에 `abc2lab.product-tls-contact/v1`을 기록한다. target_id·revision·승인/시작 단계·contact ID·host/IP/port·시간과 attempt/completed·verified/unverified 결과를 결속한다. 인증서 원문·키·TLS 오류 원문을 기록하지 않는다. 시도를 동기 저장한 뒤 연결하고 결과 저장 실패도 승인·시작을 차단한다. 완료 기록 없는 시도는 접촉 여부/결과가 불명이다. verified는 TLS 검사 결과이며 대상 승인 완료·진단 시작을 뜻하지 않는다.

## 검증과 별도 수용

만료 시간/인증서 만료의 직전·동일·직후, IP literal 고유 오류, 검사기 누락 시 TLS 0을 정상 조건과 대조한다. 만료 가드·IP 가드·nil 거부를 제거한 시험 전용 overlay에서 각각 회귀 실패를 확인한다. TLS 감사 재기동 복원·원문 비노출·감사 실패 시 접촉 0도 검사한다.

대상 승인 패널은 HTTPS·userinfo 거부, 404/501 미지원, 결과 불명 뒤 재조회, 철회, 교차 origin 응답 거부, URL 변경/중복 클릭을 단위 시험으로 확인한다. 결과 불명 상태에서 등록·승인·철회를 재전송하지 않는다.

[이전 두 URL 수용 기록](../product-targets-v2-acceptance.md)은 b676e38/1b12c51의 합성 Docker 결과다. 이번 보강은 코드·회귀 검증이며 그 기록을 새 Docker 수용으로 대신하지 않는다. 실제 유료 Qwen·공개 대상 회차는 NOT_RUN이다. E③ 일반 HTTP 후보를 확정 판정으로 승격하지 않는다.
