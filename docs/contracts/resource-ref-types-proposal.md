# resource_ref type 목록 초안

2026-11-03 · 이동찬 · **합의 전 후보 목록. Draft 유지. 실제 등록·GT 상관 활성화 아님.**

검토 기준은 `dev` `b1dea7458b8ff80744991de5b5c46c54f91465ec`다. [seam §1·§5](./idor-verifier-seam.md#1-resource_ref-규약--typeid-임시확정--민준경준)의 미정인 type 이름을 논의하기 위한 제안이다. [판정 페이지 API 예시](./verdict-record-page-api-proposal.md)의 `basket:42`도 합성 예시다. 이 목록은 엔진·KG·평가의 기존 계약이나 데이터에 아직 적용하지 않는다.

## 1. 이미 정한 형식과 이번 제안의 경계

- 전체 참조는 `type:id`이며 **마지막 콜론**으로 나눈다. type은 reset을 넘어 안정적인 논리 자원종류, id는 한 reset 세대 안의 인스턴스다. `rest:basket:42`의 type은 `rest:basket`, id는 `42`다. 이것은 문법 예시이며 `basket`의 승인된 alias가 아니다.
- E²는 전체 resource_ref와 서버의 task/run/reset/대상 인스턴스 결속으로 등록된 자원을 선택한다. 같은 id만으로 다른 type·세대의 자원을 합치지 않는다. KG 정책·canary·비교 근거도 전체 참조를 유지한다.
- owner는 별도 주체 참조다. `user`가 자원 type이 되더라도 `owner_ref`나 인증 계정을 대신하지 않는다. 계정·이메일·토큰·canary 값·URL을 type/id에 넣지 않는다. 비민감 논리 ID와 실제 대상 URL의 대응은 E² 등록 내부에서 관리한다.
- 평가만 type 접두부와 `vuln_class`로 상관한다. 엔진·KG·판정 레코드에는 GT 챌린지 키·정답 목록을 넣지 않는다. 상관 데이터의 실제 편집은 최민준이 `scripts/eval/` 안에서 별도 리뷰한다.

## 2. 명명·등록 제안

새 이름은 소문자 단수 명사를 우선하며 초기 후보는 namespace 없는 ASCII 이름으로 제한하는 안을 제안한다. 기존 계약이 허용한 type 내부 콜론을 전역 금지하지는 않는다. namespace·alias가 필요하면 독립 이름과 이관 규칙을 함께 리뷰한다.

type을 URL path의 첫 조각·화면 제목·응답의 임의 문자열에서 추정하지 않는다. E² 등록이 같은 논리 객체임을 확인한 조회만 같은 type으로 선언한다. exact method·scope URL·URL로의 해석·비변경 여부·계정·정책·표식 투영은 기존 등록 정보에서 별도로 검증한다. 이름이 같거나 목록에 있다는 사실은 송신 허가나 IDOR 지원 증거가 아니다.

## 4. 보류 이름·상관 모호성

`admin-panel`, `product`, `document` 등은 현재 합성 예시 또는 추가 의미 정의가 필요한 이름이며 초기 활성 목록에 넣지 않는다. 관리 기능·역할 상승·상태변경을 포함하는 경로는 수평 비변경 조회 v0.1의 지원 근거가 아니다. [오라클 범위](./e3-oracle.md)를 확장하려면 별도 계약과 시험이 필요하다.

같은 자원종류가 여러 검사·평가 항목에 사용될 수 있다. 현재 평가 상관은 method/action/id를 매칭 키로 쓰지 않고 type·`vuln_class`만 사용하므로, **같은 type을 여러 GT 항목에 배정해 모호성을 감추지 않는다.** 하나의 basket type으로 조회와 내용 변경의 판정을 모두 구분할 수 있다고 가정하지 않는다. 이 경우 미지원/미상관을 유지하고, 의미상 별도 자원인지 또는 평가 상관 계약을 확장할지 최민준과 따로 정한다. GT를 구분하려는 목적으로 엔진 type에 챌린지 이름을 붙이지 않는다.

합의 전에는 평가 쪽의 빈 type 매핑을 이 문서의 후보로 채우지 않는다. 후보가 나열됐다는 이유로 상관 가능·검사 완료·미탐을 산출하지 않는다. 판정 미수집과 상관 미정, 명시적 미검사는 서로 다른 상태다.

## 5. 담당·합의 순서

1. **이동찬(E²·서버):** 후보별 논리 객체·실제 등록 조회·전체 ref 생성/해석·초기 지원 여부 초안을 제시한다. 현 API 예시는 이 검증을 완료했다는 뜻이 아니다.
2. **이경준(KG·지도):** 같은 type/전체 ref가 소유·정책·canary 등록과 지도 resource 축에서 같은 객체를 뜻하는지 확인한다. 부재 중 대리 확인과 본인 사후 확인을 구분한다.
3. **최민준(판정 계약·평가):** 레코드 필드 의미·type 안정성·단일 상관 가능성을 리뷰하고, 합의한 이름만 평가 전용 상관과 시험에 별도로 반영한다. GT 키는 평가 밖으로 전달하지 않는다.
4. 세 경계의 확인 후 등록/생성기·평가 데이터·페이지 수집기의 변경을 각 담당 PR로 구현한다. 이 PR은 **최민준 리뷰를 요청한 Draft**로 유지하며 합의 전 dev에 병합하지 않는다.
