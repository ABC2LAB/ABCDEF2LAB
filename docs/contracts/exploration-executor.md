# 탐색 실행기 단계 — 결정안

상태: **결정안(2026-11-12, 최민준 결정·이동찬 리뷰).** 리뷰로 확정되기 전에는 구현하지 않는다. 일정은 적지 않는다.

[탐색 계약](exploration-boundary.md)은 탐색 실행기와 탐색 경계 사이의 경계(세션·요청·기록·중지·발견 결과)를 정했다. 이 문서는 실행기 **안쪽**, 곧 제품 흐름의 어느 단계에서 누가 어떤 도구로 탐색하는지를 정한다. 담당은 개발 계획 P1의 "탐색 실행기·수용시험(최민준)"이다. Planner·Worker 루프 복원(C19·C24~C27)은 담당 미정이라 여기서 정하지 않고, 겹치는 곳만 적는다.

## 1. 지금

- 제품 흐름의 크롤링 단계는 첫 보호 Worker 안에서 프로그램(`diagnosisflow.Controller.Crawl`)이 정적 문서를 가져온다. 가져오기는 Worker의 Bash·호출 예산·**E②** 프록시를 쓴다(`agent/e2_http.go`). 11/11 결정 전 설계라 탐색이 E②를 지난다.
- 진단 단계의 Planner·Worker 도구에는 MCP·skills가 없다(C24·C26). 원본 ARTEX는 같은 루프에 Playwright MCP와 `api-recon` skill이 있었다.
- 브라우저 샌드박스 컨테이너(`explore-browser`, 꺼짐)와 도구 고정 목록 필터(`server/mcp_tool_policy.go`)는 들어왔다. 탐색 경계(`explore-boundary`)와 단계별 relay는 이동찬 몫으로 아직 없다.

## 2. 결정안

1. **크롤링 단계를 셋으로 나눈다.** 모두 E② 밖이고 탐색 경계를 지난다(절대규칙 1·3).
   - (a) **정적 크롤**: 지금의 `Crawl`을 그대로 쓰되, 가져오기를 E② 대신 경계의 직접 입구로 보낸다(경계 relay, 이동찬). 발견 결과·상한·일시정지 처리는 지금 그대로다.
   - (b) **탐색 에이전트**: 원본 Worker 루프 하나를 탐색 전용으로 돌린다. 도구는 허용 목록의 브라우저 MCP 도구(계약 §5.1, 21개), 직접 샌드박스의 Bash(경계 직접 입구로만 나감), `api-recon` skill, 발견 보고 도구(아래 3)뿐이다. 진단 후보 제출·E③·그래프 쓰기 도구는 주지 않는다. 목표 문장은 "승인 범위 안의 화면·API를 찾아 보고한다"로 고정하고 취약점 판단을 요구하지 않는다.
   - (c) **마감**: 경계의 시간·요청 상한(`cap_exhausted`), 운영자 중지, 경계 장애(`boundary_unavailable`) 중 먼저 오는 것으로 끝낸다. 상한·경계 장애는 **실행 실패가 아니다.** 찾은 것으로 진단 단계로 넘어간다(계약 §6).
2. **진단 단계에는 브라우저 MCP가 없다.** 탐색 단계가 끝나면 서버가 MCP 연결을 닫고 브라우저 컨테이너 세션을 닫는다(계약 §6의 종료). 진단 단계 Worker의 도구 목록에 MCP 이름이 들어가면 시작을 거부한다(시험으로 고정). 진단 요청은 지금처럼 E②만 지난다(절대규칙 3).
3. **발견 결과는 프로그램이 확인한 것만 저장한다(계약 §7, 절대규칙 4).**
   - 경계 기록(실제로 오간 요청)에서 나온 것은 `observed`로, 출처는 `browser_navigation`·`browser_xhr`·`browser_form`·`api_recon_runtime`이다.
   - 에이전트가 보고 도구로 낸 것(번들·문서에서 찾은 경로)은 `inferred`로, 출처는 `api_recon_static`이다. 보고 도구는 메서드·경로·query 키 이름·JSON 본문 키 이름·content-type만 받고, 프로그램이 승인 origin·경로 범위를 다시 검사한다. 범위 밖·형식 오류는 버리고 건수만 센다.
   - 진단 결과·확정 취약점으로 다루지 않는다(절대규칙 5).
4. **세션 하나, 회차 하나.** 탐색 단계 시작 때 서버가 경계 세션을 연다(계약 §2·§9-4). 에이전트는 세션 값을 모른다. 단계가 끝나면 서버가 세션을 닫고, 닫힌 세션 뒤 요청은 경계가 `session_closed`로 막는다.
5. **평가 회차.** 경계는 계측기의 탐색 입구로, E②는 진단 입구로 보낸다(계약 §9-1). 보존 측정(수용시험 §6)은 두 입구의 합으로 원본과 비교하고, 입구별 수는 따로 싣는다.
6. **인증.** 계정 분류(계약 §8·§9-7)가 들어오기 전에는 탐색 에이전트에 인증 세션을 주지 않는다. 비인증 탐색만 한다.

## 3. 구현 순서

각 단계는 따로 PR로 올리고, 앞 단계가 없으면 그 기능은 꺼진 채로 둔다.

1. 엔진(preparation)을 탐색 제어망에 붙이고 MCP `http` 연결 설정(`explore-browser`)을 탐색 단계 전용으로 둔다. 진단 단계 도구 목록에 MCP가 없음을 시험으로 고정한다. 선행: workbench 리슨 고정(#407).
2. 탐색 에이전트 루프(2-b)와 발견 보고 도구(3). 경계가 없으면 단계를 건너뛰고(정적 크롤만) 그 사실을 회차에 남긴다.
3. 정적 크롤의 가져오기를 경계 직접 입구로 옮긴다(경계 relay 뒤, 이동찬과 같이).
4. 경계 기록 → 발견 결과(`observed`) 연결(경계 기록 형식 뒤, 수용시험 문서 §8-1).
5. 수용시험 P·B·S 시나리오를 실제 브라우저로 돌린다(수용시험 문서).

## 4. 열린 항목

1. **(이동찬) 경계 relay와 경계 기록 형식.** 3·4단계가 기다린다.
2. **(미정 담당) 루프 복원 C24~C27.** 탐색 에이전트(2-b)는 원본 Worker 루프를 쓰되 도구를 탐색용으로 좁힌다. 진단 루프를 원본으로 되돌리는 일과 같은 코드를 건드리므로, 담당이 정해지면 탐색 에이전트를 그 코드 위에 올릴지 따로 둘지 같이 정한다.
3. **탐색 에이전트의 모델 호출 상한.** 지금 제품 기본 상한(C32)은 진단 기준이다. 탐색 단계 상한을 따로 둘지는 P0 측정 뒤 정한다(측정 전 수치를 적지 않는다).
