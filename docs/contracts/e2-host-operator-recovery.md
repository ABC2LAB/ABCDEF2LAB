# E② Host 미완료 intent 운영자 복구 계약 (v1)

## 범위와 의미

정상 `sealed` 및 모든 result가 있는 `interrupted` 저널은 기존 경로를 따른다. 현재 DB head와 Host의 head 복사본, 전체 저널 MAC 및 체크포인트가 일치하지만 한 개 이상의 intent에 result가 없는 `open` 저널만 운영자 격리 대상이다. 초기 운영자 격리는 미완료 intent가 모두 GET 또는 HEAD인 경우로 한정한다. 그 밖의 메서드는 조회 시 `pending_state_change=true`로 표시하고 상태 확인·리셋 결속 계약이 마련될 때까지 해제를 거부한다. GET/HEAD도 대상에 부작용이 없다는 보증은 아니므로 운영자가 대상 상태와 다음 회차의 승인 범위를 확인한다. 결과는 송신 여부와 응답 모두 **불명**이다. 원본 사건, 현재 head, epoch, 예산, E③ 근거를 수정하거나 재전송하지 않는다.

정상 봉인과 격리는 다른 상태다. 격리 후에도 원본 head는 `open`이며 E③, 보고서 및 평가 러너에 `sealed` 근거로 제공하지 않는다. Host의 신규 실행 검사는 별도의 보호 기록을 검증한 다음에만 해당 저널을 차단 대상에서 제외한다.

## 권한과 종료 증거

복구는 Host가 시작하지 못하는 상태에서도 실행 가능한 **수동 일회성 유지보수 CLI**로만 수행한다. 일반 API, 준비 서비스, 모델, Worker에는 해당 명령과 Host 비밀 볼륨이 없다. 운영자는 제품의 준비·API·Host 등을 정지하고 별도 유지보수 컨테이너를 실행한다. 이 컨테이너는 Host 전용 볼륨, IPC 볼륨, 제품 DB 제어망, Docker daemon 소켓을 일시적으로 사용한다. Docker 소켓은 강한 호스트 권한이므로 운영자만 이 컨테이너를 실행한다.

CLI는 Docker daemon에서 자기 컨테이너의 두 볼륨 이름을 확인하고, 같은 설치의 준비·API·Workbench·Host·탐색 실행 서비스와 Host·IPC·제품 상태 볼륨을 사용하는 **다른 모든 컨테이너가 종료 상태**임을 검사한다. Runner와 프록시는 준비 서비스의 격리 수명 안에 있어 준비 컨테이너 종료와 함께 정지해야 한다. 독립된 PostgreSQL·합성 대상·합성 모델 컨테이너는 대상 송신 권한이 없고 계속 실행할 수 있다. Host 전용 `host.lock` 독점 잠금, DB 현재 epoch 및 head, MAC 저널 검증도 필수다. Docker daemon 증거가 없거나 컨테이너 목록이 불완전하거나 복구 중 상태가 변하면 거부한다. 다른 설치·다른 볼륨의 상태를 근거로 쓰지 않는다. 유지보수 CLI가 끝난 뒤에만 서비스 재시작을 허용한다.

## 불변 복구 기록

복구 기록은 Host 볼륨의 해당 run 디렉터리에 하나만 생성한다. 버전, store/epoch/generation, task/run/scope, 저널 ID, 현재 revision/checkpoint, 미완료 attempt 참조, 운영자, Docker 종료 증거 digest, 요청 시각을 담고 Host 감사 키로 도메인 분리 HMAC을 붙인다. 비밀번호·토큰·원문 URL·응답 본문은 넣지 않는다. 임시 파일 fsync 후 최종 이름에 배타적으로 link하고 디렉터리를 fsync한다. 기존 기록은 덮어쓰지 않는다. 완료 ACK가 유실되면 같은 head와 동일한 기록을 검증하여 멱등 완료로 응답할 수 있다. 기록이 사라지거나 변조되면 다음 기동은 다시 차단된다.

DB 및 Host head 불일치, MAC·체인 손상, epoch 변경, 미완료 시도 결속 오류, 살아 있는 이전 실행, 복구 대상 head 변경은 일반 운영자 복구 불가다. 게시 ACK 불명은 DB의 현재 head와 MAC 스냅샷으로 확정할 수 있을 때만 이 분류에 들어온다. 대상 HTTP 응답을 추측하지 않는다.

## 소비 경계와 호환성

격리 저널은 계속 `open`이고 기존 E③ 봉인 검증 및 공식 평가에서 실패한다. 과거 회차의 결과 불명·리셋 요구는 유지한다. 새 회차는 새 run, 정책 승인, E② lease 및 예산을 사용한다. 기존 DB schema와 역할은 변경하지 않는다. 과거 설치에는 복구 기록이 없으므로 기존 fail-closed 동작을 유지한다.

CLI의 조회와 복구는 고정 사유 코드와 비민감 집계만 출력한다. UI/API를 통해 자동 실행하지 않는다. 운영자 명령과 필요한 Docker 권한은 팀 보안 계약 리뷰 전에는 제품 기본 Compose에 활성화하지 않는다.
