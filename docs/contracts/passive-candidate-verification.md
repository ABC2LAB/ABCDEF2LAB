# 저장 후보의 수동적 독립 관찰 검증

## 범위와 버전

`passive/v1`은 후보 제출 시 모델이 고른 `related_call_refs`를 후보 증거에 포함하고 종료 시 그 사본을 대조한다. 후보 저장 이후 확보된 관찰을 찾지 못하고, 진행 중 회차는 종료 기록이 없어 확정 항목 출력 정책을 식별하지 못한다. 기존 v1 기록의 의미와 출력은 유지한다.

`passive/v2`는 후보 원본, E② 최종 호출 관찰, 검증 판정을 분리한다. 지원 유형은 `security_headers/html_nosniff_missing`과 `information_disclosure/server_version_banner`다. 확인하는 것은 실제 응답 설정 사실이며 공격 성공이나 특정 버전의 취약성은 아니다. 소유권 기반 IDOR는 E③만 판정한다. E③ 봉인과 #918 이행점검의 원본 후보·증거를 바꾸지 않는다.

## 단계와 권한

| 단계 | 입력 | 출력 |
| --- | --- | --- |
| 후보 발견 | 기존 Planner/Worker의 통제된 E② 결과 | 모델의 유형·주장·정상 가능성·주 호출 참조. 모델은 확정하지 않는다. |
| 후보 저장 | 실제 도구가 캡처한 호출, 모델 설명 | 기존 후보 fact와 digest. 원본을 덮어쓰지 않는다. |
| 요구사항 선택 | 유형과 claim | 정확한 유형별 규칙. 다른 유형은 `unsupported/type_not_supported`. |
| 근거 탐색 | 저장 후보와 같은 작업·회차의 서버 대조 E② 최종 결과 | 주 호출을 정본과 대조하고, 제출 당시 또는 이후 생긴 다른 호출을 검색한다. 모델 참조만으로 신뢰하지 않는다. |
| 프로그램 판정 | 결속된 비민감 관찰 | `confirmed`, `negative`, `insufficient`, `unsupported` 및 고정 사유·참조·관찰 digest/시각. |
| 종료 저장 | 후보, 판정, 실행 결과 | 하나의 종료 트랜잭션에 불변 `passive/v2` 스냅샷. 동일 종료 재시도는 같은 값만 허용한다. |
| 조회·내보내기 | 시작 정책 또는 종료 판정 | `diagnosis-run`과 내부 `review-json`은 미확정을 유지하고 HTML·DOCX는 확정만 출력한다. |

후보의 논리적 상태는 `saved → verifying → assessed`다. 별도 가변 상태 행을 만들지 않고 시작 정책 fact와 불변 종료 fact로 실제 상태를 결정한다. 사용자 중지, 종료 경합, 서비스 재시작으로 종료 판정이 없으면 미검증이다. 종료 저장 실패를 확정 0건으로 바꾸지 않는다. 종료 트랜잭션은 task 잠금을 잡아 중복 종료를 직렬화한다.

## 독립성과 기능 결속

서버가 E② 실행기 `CallResult`와 대조한 최종 결과만 수동적 검색 원천이다. 후보 digest, 주 `call_ref`, 작업·회차·intent와 주 관찰을 원천과 비교한다. 다른 `call_ref`와 `attempt_ref`, 최종 호출, 감사 완료, 승인된 실제 GET, HTTP 200, 완전한 비절단 응답이 필요하다. 동일 응답의 로그나 보고서 사본은 독립 근거가 아니다. 다른 대상·회차·승인 규칙은 제외한다. 응답 본문·쿠키·토큰은 새 판정 기록에 복사하지 않는다.

현재 E② `endpoint`는 마스킹 표현이라 동일 경로 패턴이 동일 기능을 뜻하지 않는다. 자동 연결은 `/{resource}`나 `/{protected}`가 없는 정확한 승인 경로 표현에 한정한다. 안정적인 비민감 기능 키가 도입되기 전에는 자원 경로를 부족 상태로 남긴다. 다른 회차·배포 버전을 기본적으로 혼합하지 않는다.

| 유형 | 확정 | 부정 | 부족 또는 충돌 |
| --- | --- | --- | --- |
| HTML nosniff | 독립 HTML 응답 2건 모두 누락 | 2건 모두 `nosniff` 있음 | 비 HTML, 미완료, 서로 다른 상태·기능 |
| Server 버전 배너 | 독립 실제 응답 헤더 2건에 같은 제품·버전 | 2건 모두 같은 제품의 버전 없는 배너 | 문서 예시, 모호한 헤더, 서로 다른 상태·기능 |

`negative`는 해당 후보의 정상 대조 결과이며 대상 전체의 안전 판정이 아니다. 근거 없음은 `independent_observation_missing`, 충돌은 `observations_inconsistent`, 원천 확인 실패는 `source_unavailable`로 남긴다. 모델 권고는 이 규칙을 바꿀 수 없다.

## 저장·보고서

새 회차 시작 시 작업·회차에 결속된 v2 출력 정책 fact를 저장한다. 진행 중에도 이 표식이 있으면 내부·공유 HTML/DOCX에 미확정 후보를 싣지 않는다. 종료 전 E③의 별도 유효 확정만 보고서 대상이다. 정책 조회 실패를 옛 완료 보고서로 추정하지 않는다. 표식 없는 과거 보고서는 이전 출력 의미를 유지한다.

종료 판정은 후보 ID, 원본 digest, 규칙 버전, 상태·사유, 사용한 호출/시도 참조, 비민감 관찰 시각과 digest를 보존한다. 보고서 로더는 저장 판정과 후보 digest를 맞춘다. 원천 조회 실패는 확정 0건이 아니다. 내부 검토와 진단 실행 결과에는 부족·미지원도 남긴다. HTML/DOCX용 출력 사본만 확정으로 추린다. E③는 기존 검증된 `ProductConfirmed`만 추가하고 모델 후보 이름으로 중복 승격하지 않는다.

## 비용·LLM·확장

v2 기본 경로는 기존 관찰만 검색한다. 추가 대상 요청 0건, 추가 모델 호출 0건, E③ 예약 변경 0이다. 기존 회차 호출·후보 수 상한을 따른다. GET도 재송신하지 않는다. 능동 검증의 E② 송신 정책·승인·예산, 비민감 기능 키는 팀 결정 전까지 구현하지 않는다.

LLM은 의미 관계와 정상 가능성을 제안할 수 있으나 판정자가 아니다. 별도 호출은 기본 경로에 넣지 않는다. 실제 효과 평가는 모델 실행 전에 정답을 고정하고 동일 사례·허용 근거를 규칙 단독과 실제 LLM 보조에 제공해 올바른/잘못된 확정·부정, 사람 검토 수, 호출·토큰·비용·추가 요청·시간을 비교한다. 모의 모델은 기능 시험으로만 기록한다. 승인된 시험 환경과 예산이 없으면 실제 호출을 수행하지 않는다.

새 유형은 정확한 키, 관찰 출처, 동일 기능·독립성, 정상 대조, 충돌·부족 사유, 좁은 확정 문구를 먼저 정의한다. 포괄 기본 규칙은 없다. XSS·SQLi·SSRF·인증 우회·신규 IDOR는 이번 버전에 없다.
