# 시험 계정 비밀번호 반사 응답 보호

VAmPI 24a·24b 후속 B다. 인증 준비 호스트가 가진 비밀번호의 일치 구간만 가려 정상 응답의 나머지를 전달한다. E③ 표식 검증기·레지스트리·저널 v3는 이 변경에 포함하지 않는다.

## model_visible_v1 (2026-11-23 사용자 결정)

대상에서 온 정보는 외부 모델로 나가도 되고, 그 책임은 사용자에게 있다고 동의 문장으로 공지한다. 그래서 새 시험 계정 실행은 `auth.password_response: "model_visible_v1"`로 결속한다(제품 계정 결속이 생성, `auth_prep` 규칙·`test_account_passthrough` 필요, 다른 값은 적재 거부는 아래와 같음).

- **모델 쪽**: 대상 응답 본문·헤더에 비친 비밀번호를 보류하지도 가리지도 않고 도구에 준다. 영수증은 보류가 아니라 실제대로(`complete`)다. 모델에 가는 도구 출력 가림(`RedactOutput`)도 비밀번호를 가리지 않는다.
- **저장 기록(2026-11-26 DLP 폐기로 바뀜)**: 제품 기록은 내부 담당자만 보므로 비밀번호·세션·대상 응답을 가리지 않는다(CLAUDE.md 절대규칙 2). `RedactRecord`는 E③ 표식과 우리 제어 비밀(설정한 보호 값)만 가린다. 기록은 뒤에 모델 입력(그래프 요약·후보 검증)으로 다시 갈 수 있어서 표식·제어 비밀은 늘 가린다. `model_visible_v1` 실행은 비밀번호를 등록할 곳이 없어 `AddProtectedPasswords`가 받기만 하고(짧은 비밀번호 계정도 결속, 6바이트 하한 없음), 시험 계정 실행은 세션 값(인증 준비·대상 발급)을 가림 목록에 넣지 않는다. 그래서 짧은 발급 세션이나 가림 자리 때문에 응답을 보류하지 않고, 세션 가림 칸 상한(#840)에도 닿지 않는다. 시험 계정 실행의 모델 출력(`RedactOutput`)도 세션·`Set-Cookie`·요청 자격 자리를 가리지 않는다. 아래는 그 전의 기록이다. 이전 규칙: `RedactRecord`는 정책과 상관없이 비밀번호를 가렸다. 쓰는 곳은 활동 기록(도구 결과·모델 글·메타데이터), 진단 후보 근거(명령·도구 출력·자유문장), 그래프 도구 입력(사실·의도 저장), 진단 관찰(엔드포인트·서버 헤더), 승인 미리보기 본문(모델 단계·확정 단계), 감사 추적의 도구 결과다. 원격 E²는 `redact_record` 연산으로 같은 가림을 한다.
- **그대로인 것**: 일반 보호 값(우리 통제 비밀)이 비친 응답은 전체 보류한다(`AddProtectedValues`). 로그인은 모델이 직접 한다(2026-11-26, 확정 단계 다시 로그인만 프로그램). 인증 준비가 비밀번호를 세션으로 되돌려 받으면 세션 전달을 거부한다. 세션 값의 등록·가림은 위 DLP 폐기로 시험 계정 실행에서 걷었다.
- **모델 요청 속 비밀번호 거부는 없앴다(사용자 결정 2026-11-26).** 탐색·진단 모두 모델이 등록 계정 아이디·비밀번호로 직접 로그인한다([모델 로그인 시도 기록 계약](model-login-attempts.md), CLAUDE.md 절대규칙 2). 그래서 E②는 모델 요청에 등록 비밀번호가 들어 있다는 이유로 막지 않는다. 메서드·범위·자격 헤더 모드·예산 검사는 그대로다. 11/23의 거부 규칙(모델 요청의 URL·헤더·본문에 등록 비밀번호가 있으면 `policy_denied`)은 이 변경으로 대체됐다.
- **남는 것**: 감사 추적의 도구 입력은 승인 훅과의 대조 키라 원문이다.
- 이전 `mask_spans_v1`·칸 생략 실행은 아래 의미 그대로 읽는다.

## 정책과 이전 실행

보호된 실행 정책의 선택 칸 `auth.password_response: "mask_spans_v1"`가 있는 시험 계정 실행만 구간 가림을 사용한다. `auth_prep` 규칙도 있어야 한다. 누락된 이전 정책은 전체 보류를 유지한다. 빈 값·null·모르는 값·대소문자 별칭은 적재를 거부한다. 모델·HTTP 입력·환경 변수가 이 모드를 정하지 않는다.

제품은 현재 승인된 시험 계정을 새 실행에 결속할 때 이 칸을 생성한다. 계정 선택 digest와 E② 정책 내용 지문에 모드를 넣으므로 이전 결속 디렉터리를 재해석하거나 덮어쓰지 않는다. 이전 정책의 칸 생략 시 정본·digest는 그대로다. 저장 보고서에서는 그 실행 정책의 모드를 복원하며 현재 계정 선택으로 대체하지 않는다. 이 기능을 모르는 구버전 reader는 새 정책을 명시적으로 거부한다.

호스트 API `AddProtectedPasswords`는 일반 `AddProtectedValues`와 구별한다. 비밀번호가 일반 제어 비밀과 같은 값이면 일반 보호 값의 전체 보류가 우선한다. 출력·근거·활동·보고서 가림에는 두 종류 모두 포함한다. 기존 세션 등록·JWT 조각 가림·모델 세션 전달 승인은 유지한다. 인증 준비에서 비밀번호 자체 또는 지원 인코딩으로 표현된 비밀번호를 세션으로 되돌려 주면 세션 전달을 거부한다.

## 지원하는 표현

- 완전히 읽은 UTF-8(또는 ASCII) `text/plain`, `text/html`, `application/json`, `+json`, `application/x-www-form-urlencoded` 본문만 지원한다. JSON은 전달 전후 모두 유효해야 한다.
- 등록한 값과 Unicode 단순 대소문자 무시 대조(`strings.EqualFold`와 같은 rune 동등성)로 일치한 구간, 단일 JSON 문자열 escape(`\uXXXX`, surrogate pair 포함), HTML 숫자·이름 entity, URL `%XX`를 한 번 해석한 사본에서 일치한 구간을 원문의 위치로 되돌려 가린다. form의 `+`는 공백으로 해석한다. UTF-8 바이트 수가 다른 대소문자 변형도 원문 전체 구간을 가린다. NFC/NFKC·문자 확장·임의 변환은 하지 않으며 비민감 원문을 정규화하지 않는다.
- 비민감 원문 바이트는 보존한다. 대체 문자열은 `[REDACTED]`, form은 `%5BREDACTED%5D`다. 대체 결과가 보호 값과 다시 겹치거나 유효한 JSON을 만들지 못하면 전체 보류한다.
- 이미 일치한 비밀번호 안의 리터럴 특수문자는 추가 인코딩으로 오인하지 않는다. 그 밖에서 첫 해석이 다음 escape/entity/percent 해석을 만드는 중첩 표현은 전체 보류한다. 독립된 다른 필드의 단일 escape는 중첩으로 간주하지 않는다.

이것은 호스트가 등록한 값과 위 지원 표현의 제한된 검사다. 임의 변환·알 수 없는 암호화까지 알아보는 범용 DLP로 주장하지 않는다. 알려진 표준/base64url 비밀번호 표현도 전달하지 않고 보류한다. 별도 charset·binary MIME·압축·부분 응답(206/Content-Range)·불완전 본문·지원하지 않는 entity·잘못된 escape/percent·검사 한도 초과는 성공적인 가림으로 해석하지 않는다. JSON 밖에서 JSON escape가 아닌 리터럴 역슬래시는 그대로다.

응답 헤더·trailer의 이름/값·상태 줄·protocol도 같은 대소문자 무시 대조를 사용한다. Go가 헤더/트레일러 이름을 정규화한 경우도 포함한다. 메타데이터에는 기존 검사도 먼저 적용해, 이름의 `ToLower` 대조가 단순 fold와 달리 찾는 `İ/i` 같은 경우도 계속 보류한다. 비밀번호가 관측되거나 검사할 수 없으면 본문만 고쳐 전달하지 않고 전체 보류한다. 특히 Set-Cookie/Authorization 반사를 가린 세션으로 바꿔 발급하지 않는다. 일반 제어 비밀·비시험 계정의 기존 응답 보류도 유지한다.

## 상한과 HTTP·감사 의미

등록 값은 기존 보호 값 하한 6바이트·상한 8KiB, 실행당 비밀번호 64개 이내다. 중복 재등록은 세대·개수를 늘리지 않는다. 전체 등록과 검사 상한 검증은 원자적이며, 새 비밀번호로 `검사 상한 ≥ 본문 상한 + 가장 긴 보호 값 − 1`을 깨면 등록을 거부한다. 읽는 동안 보호 목록 세대가 바뀌면 응답은 전체 보류한다.

각 단일 인코딩 해석과 UTF-8 길이가 바뀌는 대소문자 접기는 각각 최대 65,536개, 일치 구간은 최대 4,096개다. 길이가 같은 ASCII 대소문자 치환은 위치표 상한을 쓰지 않는다. 임계점을 넘거나 대체 후 본문이 승인된 응답 상한을 넘으면 전체 보류한다. 불완전 본문의 앞부분을 가림 성공으로 전달하지 않는다. 비밀번호 없는 이전 정책의 기존 상한 처리는 바꾸지 않는다.

부분 가림 후 실제 HTTP status와 안전한 헤더는 유지하고 Content-Length를 다시 계산한다. 원래 표현의 chunk/trailer, ETag·Content-MD5·Digest·Content-Digest·Repr-Digest는 제거한다. 압축을 풀어 준 것으로 가장하지 않는다.

송신·응답을 실제 관측했으므로 `allowed`, `forward_attempted`, `response_received`는 실제대로다. **원래 표현의 일부는 보류했으므로** 기존 v2 영수증의 `reason: "withheld"`, `response_complete: false`를 유지한다. 길이 절단은 아니므로 `response_truncated: false`다. 결과 불명으로 세지 않는다. 전체 보류와 부분 가림은 기존 영수증 필드만으로 모두 구별할 수 없으며, 새로운 필드나 기존 기록 재해석을 추가하지 않는다. 실제 전달 본문과 해당 실행의 정책 지문을 함께 확인한다.

## 검증 범위

`TestPasswordResponseNeverWeakensLegacyDetection`은 기존 `protectedHTTPValuesSafeLocked`를 차등 기준으로 사용해 본문·헤더/trailer 이름·값·상태 줄·protocol에서 기존 검출을 잃지 않는지 확인한다. 대소문자 변형은 기존 검출 여부와 별개로 가림/보류를 요구한다. 실제 HTTP의 이름 정규화, 인코딩 해석과 UTF-8 길이 변경의 원문 위치, 위치표 상한도 별도 시험한다.

합성 자격만 사용한다. 소유 HTTP 수신 서버의 정상/반사/인코딩/부분/압축 응답, 실제 E② 호출·예산·감사, 파일 factory의 인증 준비·재로그인·세션 사용, 구형·신형 정책 지문과 계정 결속 복원, 안전한 실패를 대조한다. 본문·비밀번호 원문은 감사·진단 로그에 넣지 않는다. 실제 Qwen/VAmPI 새 회차와 Workbench 브라우저 시험은 별도 승인 전 `NOT_RUN`이다.
