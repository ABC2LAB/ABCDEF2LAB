# 실행 문맥의 런타임 콜백

서버 초기화와 테스트가 agent 패키지의 전역 함수 포인터를 교체하는 동안 기존 Worker·Planner가 이를
읽어 data race가 발생했다. 동시 접근을 잠그는 것만으로는 나중에 생성한 서버의 DB·스킬·언어 콜백을
기존 서버가 사용하는 문제를 막을 수 없어, 런타임 콜백의 소유자를 실행 문맥으로 고정한다.

`agent.RuntimeHooks`는 도구 추가·해석, 프롬프트, 출력 언어, run/task 마무리와 예산, finding traffic
설정의 콜백 9개를 묶은 값이다. `WithRuntimeHooks`가 문맥에 복사하고 `RuntimeHooksFrom`이 같은 값을
반환한다. 별도 전역 기본 콜백은 없으며 문맥이 없으면 기존 내장 기본값을 사용한다.

각 Server는 자신의 DB·스킬 디렉터리·도구 제공자·언어 캐시를 참조하는 묶음을 한 번 만들고,
background goroutine이 시작되기 전에 서버 문맥에 붙인다. 요청·엔진 시작·분리된 Worker 경계도
해당 서버의 문맥을 전달한다. 취소·deadline·RunInfo·승인·side-question 문맥의 다른 값은 유지한다.

콜백 선택은 같은 소유자를 유지하지만 콜백의 결과를 고정하지는 않는다. DB 프롬프트와 언어 캐시,
finding traffic 설정은 기존처럼 읽을 때의 값을 사용한다. 이미 조립한 도구도 실제 finding/hint 쓰기
시점에 같은 서버의 설정을 다시 확인한다. 콜백과 MCP 정리는 전역 registry 잠금을 잡지 않고 실행한다.

직접 전역 함수를 대입하던 내부 호출·테스트는 명시적인 문맥 주입으로 전환한다. 모델 프롬프트 본문,
기본 도구·허용 정책·마무리 예산 규칙은 변경하지 않는다. 패키지 밖에서 기존 전역 변수를 주입하던
확장도 실행 문맥의 RuntimeHooks로 옮겨야 한다.

backend 메시지 카탈로그와 알림 표시 언어는 별개의 process 공통 선택이다. 이 콜백은 동기화된
setter로 교체하고 잠금 밖에서 호출한다. agent의 서버별 출력 언어와 달리, 이 변경이 모든 HTTP 응답·
알림의 다중 서버 언어 격리를 제공하지는 않는다. 여전히 마지막으로 등록한 표시 언어 resolver를 사용한다.

회귀 시험은 도구 조립 중 콜백 묶음 교체, 동시 A/B 문맥, 재진입·정리, 값 복사·기본값과 실제 Server
두 개의 스킬/언어 소유권을 검증한다. 실제 서버 시험은 전용 PostgreSQL을 지정해 실행한다.
