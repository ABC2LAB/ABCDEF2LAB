# 시험 계정 분류와 로그인 복원 결정안 (C14·탐색 계약 §9-7)

상태: **결정안**(최민준 작성, 이동찬·윤재상 리뷰, 화면·흐름은 이경준). 리뷰로 확정되기 전에는 구현하지 않는다. 확정되면 [개발 계획의 계정 항목](archive/development-plan-v3.md#1111-개선-순서--원본-능력-보존-우선), [탐색 계약](contracts/exploration-boundary.md) §8·§9-7, [수용시험](evaluation/browser-acceptance.md) S07~S09를 같은 PR 묶음으로 고친다.

> **2026-11-26 대체(사용자 결정).** 이 결정안의 다음 부분은 [모델 로그인 시도 기록 계약](contracts/model-login-attempts.md)과 CLAUDE.md 절대규칙 1~3(2026-11-26판)으로 대체됐다.
> - 결정 1·2의 `시험 계정` 분류·표시: 프로그램은 계정을 분류하지 않는다. 대상에 등록된 계정을 쓰고, 시험 계정만 등록하라는 공지는 사용자 책임이다.
> - 결정 3(로그인은 프로그램의 인증 준비가 한다)과 결정 4의 세션 지침 줄·`refresh_session`: 탐색·진단 모두 모델이 등록 계정 아이디·비밀번호로 직접 로그인하고, 받은 세션을 스스로 실어 보낸다. 같은 아이디로 연달아 실패한 로그인은 회차당 3번까지다.
> - '하지 않는 것'의 "모델이 비밀번호를 입력하는 로그인"과 S09의 "프로그램이 모델 입력에 비밀번호를 넣는 일은 없다".
> - 그대로인 것: 결정 4의 자격 헤더 통과 모드와 승인 origin 한정, 결정 5의 실계정 보호 세션 주입 범위 밖, 확정 단계(E③) 다시 로그인(모델 로그인 기록 재사용이 들어오기 전까지 지금 로그인 방식으로 프로그램이 한다).

## 왜

[개선 목록](control-restore-backlog.md) C14: 제품 진단은 로그인한 상태로 대상을 볼 수 없다.

- E②가 모델이 쓴 `Authorization`·`Cookie` 요청을 보내기 전에 거부한다(`preserve` 모드). 평가 전용 `evaluation_caller_passthrough`만 통과시킨다.
- `Set-Cookie`·`WWW-Authenticate` 같은 자격 응답은 통째로 보류하고 결과 불명으로 센다. 로그인 응답이 오면 그 call이 결과 불명 상한에 닿는다.
- 제품 URL 진단 설정은 대상 자격(`rule.Credentials`)을 받지 않는다.

원본 ARTEX는 Worker가 curl로 로그인하고 받은 쿠키·토큰으로 다음 요청을 보낸다. 인가·IDOR 진단은 계정 둘 이상의 세션이 있어야 시작할 수 있으므로, 이 차이가 우리 초기 집중 영역의 성능을 가장 크게 깎는다.

이미 정한 것(개발 계획 11/11 계정 결정): 모델 입력에는 `시험 계정` 표시가 붙은 소유·승인된 일회용 시험 계정에서 대상이 발급한 세션 값만 넣을 수 있다. 비밀번호는 어떤 계정이든 모델에 넣지 않고 로그인은 프로그램이 한다.

**11/23 갱신(사용자 결정)**: 대상에서 온 정보(대상 응답·도구 출력, 대상이 돌려준 비밀번호·개인정보 포함)는 외부 모델로 나가도 된다. 그 책임은 사용자에게 있다고 공지·동의 문장에 넣는다. 그래서 대상 응답에 비친 시험 계정 비밀번호는 세션 값과 같이 **모델에는 주고**, 저장 기록(도구 출력 기록·근거·활동·보고서·화면 API)에서만 가린다(E② `auth.password_response: "model_visible_v1"`, 아래 "비밀번호 반사 응답"). 바뀌지 않는 것은 셋이다. 로그인은 프로그램이 하고 모델이 비밀번호를 입력하지 않는다(모델 요청에 등록된 시험 계정 비밀번호가 들어 있으면 E②가 `policy_denied`로 거부한다. 모델은 세션 값과 `refresh_session`을 받는다. 대상이 흘린 다른 사용자 비밀번호는 E②가 모르는 값이라 막지 않는다). 우리 통제 비밀(모델 API 키, 관리자 비밀번호, 경로 가림 키, E③ 표식 값, 승인 ID 등)은 모델 입력에 넣지 않고, 응답에 비치면 지금처럼 보류한다. 고객 실계정 자격은 모델 밖이다. 표시는 프로그램이 보호된 계정 등록 정보로 판정하고, 없거나 판단할 수 없으면 실계정이다. 외부 API 모드에서는 사전 공지·승인 회차에서만 켠다. 이 결정안은 그 결정의 남은 항목(저장 위치·승인 주체)과 E② 쪽 동작을 정한다.

## 결정 1 — 계정 등록은 대상 등록에 붙인다

- 계정은 제품 대상 등록 기록(`productTargetRecord`, 보호 저널)에 대상별 목록으로 둔다. 다른 대상의 진단에서 쓸 수 없다.
- 칸: 계정 라벨(화면·감사용 이름, 사용자명 원문 아님), 분류(`test`·`real`, 기본 `real`), 로그인 방식 참조(결정 3), 자격 참조, 등록자, 분류한 사람·시각·진술 해시.
- 비밀번호·API 토큰 같은 자격 값은 저널에 넣지 않는다. 서버 uid만 읽는 보호 파일(`privateinput`과 같은 0600·소유자 검사)에 두고 저널에는 참조와 해시만 남긴다. 감사·로그·화면·보고서에는 라벨만 나간다.
- 대상 판(revision)이 바뀌면(재승인) 그 대상 계정의 분류는 `real`로 돌아가고 다시 표시해야 한다. 대상 범위가 바뀐 뒤에도 같은 계정이 시험용인지는 다시 확인할 일이다.

## 결정 2 — `시험 계정` 표시는 대상 승인자가 붙인다

- 표시는 그 대상을 승인한 운영자(대상 승인 권한 모델의 승인자, DNS 소유 증명과 본인 진술을 한 사람)만 붙인다. 한 단계다: 등록자의 표시 요청·승인 대기(`test_pending`) 단계는 두지 않는다(표시한 사람 = 승인자라 감사가 단순하다). 진술 문구: "이 계정은 우리 조직이 소유한 일회용 시험 계정이고 실제 사용자 데이터가 없으며, 대상 운영 주체가 이 계정으로 시험하는 것을 허락했다."
- 표시를 떼는 것은 그 대상에 권한이 있는 누구나 할 수 있다(더 안전한 쪽). 지금 대상 권한은 등록한 운영자 한 사람이라 표시·해제 권한이 같다. 권한 모델이 넓어지면 해제 쪽만 넓힌다.
- 승인이 만료된 대상의 계정은 표시가 남아 있어도 `real`(사유 `target_expired`)로 읽는다. 목록과 실행 결속이 같은 판정을 쓴다. 화면은 목록 응답의 진술 문장(`account_statement`)을 그대로 보여 주고 동의를 받는다.
- 붙이고 떼는 일은 둘 다 감사 기록에 남긴다(누가·언제·어느 대상 판·어느 라벨). `real`로 돌아간 사유를 칸으로 나눈다: `target_reapproved`(결정 1의 재승인)·`manual_unmark`(사람이 뗌). 실행 중 표시를 떼서 멈춘 실행은 실행 종료 사유에 같은 값을 남겨 화면이 "대상 재승인으로 해제"·"표시 해제로 송신 정지"를 따로 보인다.
- 실행 시작 때 서버가 계정 등록 정보로 분류를 판정해 실행 결속에 넣는다(정책 지문에 계정 라벨·분류·자격 참조 해시). 실행 중 표시를 떼면 그 실행의 새 송신은 멈춘다(권한 철회와 같은 사건). 저장소를 읽지 못하면 실계정이다.
- 평가 회차는 지금처럼 러너가 공개 연습 대상의 fixture 계정을 시험 계정으로 선언한다(`evaluation_caller_passthrough`). 제품 분류와 섞지 않는다.

## 결정 3 — 로그인은 프로그램의 인증 준비가 한다

- 로그인 방식은 대상별 설정이다. 앱의 로그인 경로·필드 이름·토큰 위치를 코드에 넣지 않는다(CLAUDE.md 하드코딩 금지). 설정 칸: 메서드·경로(승인 경로 접두 안이어야 함)·본문 형식(form·JSON)·사용자명/비밀번호 필드 이름·세션 위치(`Set-Cookie` 이름 목록 또는 JSON 응답의 필드 경로 → 보낼 헤더 이름과 접두).
- 인증 준비는 Worker가 아니라 서버가 실행 시작 때 `test` 계정마다 한 번 보낸다. 실계정은 로그인하지 않는다(이 결정안 범위에 실계정 세션을 쓰는 곳이 없으니 송신을 줄이고 실계정 잠금 위험을 없앤다). 이 요청도 E②를 지난다(승인 origin·IP·TLS·감사). 로그인 메서드가 쓰기(POST)여도 로그인 경로 하나에만 허용하고, 진단 쓰기 승인 범위·쓰기 수와 따로 센다(수용시험 S07). 예산에서는 센다.
- 로그인 실패·세션 위치를 못 찾음은 그 계정 없이(비인증으로) 진행하고 실행 기록에 계정별로 남긴다(S08). 칸은 실행 결과의 `account_auth`(계정 라벨 → `authenticated`·`login_failed`·`session_not_found`·`result_unknown`)다. 인증 성공으로 세지 않고, 화면·보고서는 그 계정 기준 인가 결과를 "접근 차단 확인"으로 읽지 않는다(절대규칙 5).
- 로그인 실패는 자동으로 다시 시도하지 않는다. 결과 불명인 로그인 요청도 다시 보내지 않는다(결과 불명 쓰기 재전송 금지와 같은 원칙). 대상의 계정 잠금(N회 실패)에 걸리면 그 회차의 인가 진단이 전부 비인증이 되기 때문이다.
- 세션 만료는 Worker가 새 로그인을 요청하는 도구(`refresh_session`, 계정 라벨만 받음)로 다시 준비한다. 성공한 재로그인의 누적 횟수는 제한하지 않는다. 실행 전체에서 계정별 **연속 실패 3회**에 닿으면 남은 실행 동안 그 계정의 재로그인을 막고(`refresh_limit`), 성공하면 연속 실패 수를 초기화한다. 이전 재로그인 완료부터 다음 시작까지 계정별 **최소 10초**를 둔다(`refresh_cooldown`, 새 로그인 송신 없음). 첫 인증 준비와 간격·상한 거부는 연속 실패에 세지 않는다. 상한·간격 거부는 해당 명령만 실패시키며 Worker는 다른 허용 작업을 계속한다. 기존 실행 시간·요청 예산과 권한 철회·감사 오류의 정지 조건은 그대로 적용한다.

## 결정 4 — 시험 계정 실행은 자격 헤더를 통과시킨다

- 실행에 시험 계정이 하나 이상 결속되면 E② 헤더 모드를 새 `test_account_passthrough`로 둔다. 동작은 `evaluation_caller_passthrough`와 같다: 모델이 쓴 `Authorization`·`Cookie` 값을 바꾸지 않고 보낸다(승인 origin·경로·메서드·예산·감사 검사는 그대로). 빈 값·Connection으로 지정한 자격 헤더 거부도 같다.
- 자격 응답 헤더(`Set-Cookie` 등)는 이 모드에서 보류하지 않고 도구 출력에 그대로 준다. 대상이 발급한 세션 값이 모델로 가는 것이 11/11 결정의 허용 범위다.
- 인증 준비로 얻은 세션은 Worker 지침에 "계정 라벨 → 보낼 헤더" 한 줄로 준다(시험 계정만). 모델은 원본처럼 curl에 헤더를 직접 쓴다. 다른 계정 세션으로 바꿔 보내는 인가 진단이 이것으로 된다.
- 모델이 쓴 값이 이 실행에서 발급된 세션인지 대조하지 않는다. 변조한 토큰(서명 없는 JWT 등)을 보내는 것도 인증 진단이기 때문이다. 자격이 모델에서 대상으로 가는 방향은 비밀 유출이 아니다. 그래도 자격 헤더는 승인 origin 요청에만 나간다(외부 호스트는 E② origin 검사가 그대로 막는다).
- 외부 API 모드에서는 사전 공지·승인을 받은 회차에서만 이 모드를 켠다(실행 생성 때 승인 기록 확인). 아니면 시험 계정도 결정 5처럼 다룬다. 구현: 초안 입력 `external_test_accounts`(운영자 진술, 원본 요약에 들어감)가 있을 때만 외부 API 실행에 시험 계정을 결속하고, 실행 launch로 서버에 넘긴다. 서버는 그 값이 없는 외부 API 실행의 인증 준비 정책을 거부한다. 동의는 고정 진술의 해시·주체·시각·작업으로 대상 계정 저널(`external_consent`)에 남고, 대상 승인자만 남길 수 있다([URL OpenRouter 연결](url-openrouter-integration.md)).
- 기록 경계는 지금과 같다: 감사 이벤트·결과 projection·보고서·근거 파일에 헤더 값을 넣지 않는다. 엔진 안 대화 기록·`tool_input`의 세션 값은 실행 데이터 보관·삭제 규칙을 따른다(시험 계정 세션이라 허용, 비밀번호는 들어가지 않음).
- 화면·API로 내보내는 것도 기록 경계에 든다: 운영 API가 화면으로 내보내는 `tool_input`(승인 대기 목록 포함)·요청/응답 원문·탐색 기록·로그에서 서버가 자격 헤더(`Authorization`·`Cookie`·`Set-Cookie` 등)의 값을 가린다(이름만 남김). 지금 승인 화면은 브라우저에서 가리는데(`web/src/lib/diagnosis/redact.ts`), 그것은 이중 방어로만 남긴다. 저장된 값은 실행 데이터 보관 규칙을 따르지만 화면·공유 로그로 나가지 않는다(절대규칙 2 "공유 로그").

## 결정 5 — 실계정과 계정 없는 실행

- 실계정·계정 없는 실행은 지금처럼 모델이 쓴 `Authorization`·`Cookie`를 거부한다(`preserve`).
- 자격 응답은 [C16 결정안](contracts/e2-proxy-transfer-scope.md#본문-상한과-표현-보류--c16-결정안-2026-11-12-최민준-결정이동찬-리뷰)대로 `withheld`로 센다. 결과 불명이 아니므로 그 call을 멈추지 않는다. 이 부분은 계정 기능 없이 C16 구현으로 먼저 들어간다.
- 실계정으로 인증한 진단(보호 세션 주입: 모델은 라벨만 쓰고 E②가 값을 넣는 `protected_session_proposal`)은 이 결정안 범위 밖이다. 실계정 세션은 계속 모델 밖에 두고, 필요해지면 따로 결정한다.

## 탐색 쪽

- 탐색 실행기는 인증 준비가 만든 시험 계정 세션을 브라우저 프로필에 넣는다(계약 §8). 헤더를 브라우저 전체 요청에 넣는 방식은 쓰지 않는다. 탐색 경계는 승인 origin 요청에만 쿠키가 가는지 수용시험에서 본다.
- 실계정 세션은 탐색에서도 쓰지 않는다.

## 수용시험 개정

- S07: 인증 준비 요청이 진단·크롤링 쓰기 수와 따로 세어지고 예산에는 들어간다.
- S08: 로그인 실패·세션 위치 불일치가 비인증 진행과 계정별 실패 기록으로 남는다.
- S09: 비밀번호 표식은 로그·근거 파일·보고서·화면 API 응답에 없다. 모델 입력에는 11/23 갱신 뒤 대상이 응답으로 비춘 경우에만 있을 수 있다(`model_visible_v1` 실행). 프로그램이 모델 입력에 비밀번호를 넣는 일(로그인·지침 줄)은 여전히 없다. 시험 계정 세션 표식은 `test_account_passthrough` 회차의 모델 입력에만 있을 수 있고 감사·근거 파일·보고서·화면 API 응답(승인 대기 `tool_input`·요청/응답 원문·탐색 기록)에는 없다. 실계정 세션 표식은 모델 입력에도 없다.

## 구현 순서

1. C16 `withheld`(결정 5의 자격 응답) — 계정과 무관하게 결과 불명 정지를 없앤다. 최민준 구현, 이동찬 페어 리뷰.
2. 계정 등록·분류 저장과 관리 API(결정 1·2) — 서버 최민준, 화면 이경준.
   - 진행(2026-11-13): 라벨·분류·표시/해제·감사 저널과 관리 API를 넣었다(대상 등록 디렉터리 안 별도 보호 저널 `accounts/`, 표시는 그 대상 판에만 묶여 판이 바뀌면 `target_reapproved`로 real, 해제는 `manual_unmark`, 진술은 SHA-256만). 대상 등록 기록 자체(`productTargetRecord`)는 판·상태 전이 검증이 엄격해서 계정 줄을 같은 저널에 섞지 않았다. 자격 값(보호 파일·참조·해시)은 로그인 방식과 같이 3에서 넣는다. 실행 결속(실행 시작 때 분류 판정·실행 중 해제 시 정지)도 3이다.
3. 인증 준비(결정 3)와 실행 결속·정책 지문.
   - 진행(2026-11-13): 대상 로그인 방식 설정(승인 경로 접두 안의 정규 경로·POST·form/JSON·필드 이름·세션 위치)과 계정 자격 저장(준비 프로세스의 보호 파일 0600 원자 쓰기, 저널에는 SHA-256만, 파일이 바뀌면 자격 없음으로 봄)을 넣었다. 관리 API `…/login`, `…/accounts/{label}/credential`. 보호 파일에는 쓸 때마다 새 난수를 넣어 저널의 파일 해시로 사용자명·비밀번호를 사전 대조하지 못하게 했다. 시험 계정 표시를 떼면 그 계정의 자격 파일을, 대상을 철회하면 그 대상 계정들의 자격 파일을 지운다(실계정 자격을 필요 이상 들고 있지 않는다). 승인이 만료된 대상의 자격은 철회 때 지워진다. 실제 인증 준비 요청(E② 경유)·실행 결속은 아직이다.
4. `test_account_passthrough`(결정 4)와 Worker 지침의 세션 줄, `refresh_session`.
   - 진행(2026-11-13): 넣었다(#522·#550, 외부 API 실행의 회차별 동의 #552·#561·#568). 아래 "구현 설계" 절 (c) 문단.
5. 탐색 실행기 브라우저 프로필 세션, S07~S09 수용시험.
   - 진행(2026-11-14): S08·S09 실제 회차를 돌렸다(아래 "실제 회차 확인"). 남은 것: 탐색 실행기 브라우저 프로필 세션, S07(인증 준비 요청을 따로 세는지) 실제 회차 대조, S08 보고서·화면 표시, S09 대상 응답의 비세션 토큰 분류와 모델 입력·DB 활동 기록 처리 결정.

## 구현 설계 — 인증 준비와 실행 결속(3단계 나머지·4단계)

상태: **설계안**(2026-11-13, 최민준 작성, 이동찬·윤재상 리뷰). 위 결정 3·4를 E②와 실행 흐름에 어떻게 넣을지다. 리뷰 뒤 이 순서로 구현한다. 계정 저장·분류·로그인 방식·자격 보호 파일은 #514·#515에 있다.

1. **로그인 전용 규칙(E② 정책).** 실행 정책에 대상 로그인 경로 하나만 가리키는 규칙을 따로 둔다: `purpose: "auth_prep"`, 메서드 `POST`, 경로는 접두가 아니라 **정확히 그 경로**. 모델이 쓴 요청(Bash·WebFetch)의 규칙 찾기는 이 규칙을 건너뛰어, 진단 쓰기 승인이 없는 실행에서도 로그인 POST만 열리고 모델은 그 경로에 쓰기를 보낼 수 없다. 이 칸은 값이 있는 정책만 정책 지문에 들어간다(로그인 없는 실행의 지문·공식 평가 템플릿은 그대로).
2. **프로그램 소유 송신.** 실행 시작 때 서버가 계정마다 `Execution.AuthPrep(ctx, request, extract)`를 한 번 부른다. 요청 본문(로그인 방식의 form/JSON)은 서버가 자격 보호 파일로 만들고, E②는 로그인 규칙으로만 판정·감사(본문은 감사에 안 남음, 지금과 같음)·예산 계수를 한다. 응답은 모델로 가지 않고 `extract` 콜백(로그인 방식의 쿠키 이름 또는 JSON 필드 경로)만 본다. 콜백은 보낼 헤더(`Cookie` 또는 설정 헤더)만 돌려주고 본문은 지운다. 자동 재시도 없음, 결과 불명이면 다시 보내지 않고 그 계정은 `result_unknown`.
3. **계수.** 영수증의 규칙 참조가 로그인 규칙이라 진단 쓰기 수·쓰기 승인 범위와 따로 센다(S07). 대상 요청 예산(승인 회차 N)에는 들어간다. 기록 형식 칸은 늘리지 않는다(규칙 참조로 구분).
4. **세션 값의 자리.** 세션 값은 실행 메모리에만 있고 디스크·저널·감사·결과 projection·보고서에 쓰지 않는다. 실행 결과에는 `account_auth`(라벨 → `authenticated`·`login_failed`·`session_not_found`·`result_unknown`)만 남긴다. 로그인에 쓴 비밀번호는 보내기 전에 E② 보호 값으로 등록해, 대상이 다른 응답에 비밀번호를 되돌려 주면 그 응답을 보류하고 출력에서도 가린다(6바이트 미만 등 보호할 수 없는 비밀번호로는 로그인하지 않음, S09). 세션 값은 E②의 **출력 가림 목록**(`RedactOutput`)에 넣어 도구 출력·근거·보고서에서 가리고, 응답 표현 보류(보호 값 반사 검사)에는 넣지 않는다 — 시험 계정 실행에서 토큰을 되돌려 주는 응답을 통째로 보류하면 인가 진단이 깎이기 때문이다. 모델은 Worker 지침 줄(결정 4)로만 세션 값을 받는다(S09: 세션 표식은 모델 입력에만).
5. **실행 결속.** 실행 시작 때 계정 목록을 `accountView`(목록과 같은 판정, 만료·판 변경이면 real)로 읽어 `test`이고 자격·로그인 방식이 있는 계정만 고른다. 고른 라벨·분류·자격 해시·로그인 방식 해시를 실행 결속(정책 지문의 계정 칸)에 넣는다. 실행 중에는 대상 승인 확인과 같은 주기로 다시 판정해, 결속한 계정이 `test`가 아니게 되면(해제·만료·판 변경) 새 송신을 멈춘다(권한 철회와 같은 사건, 사유 `manual_unmark`·`target_expired`·`target_reapproved`를 실행 종료 사유에).
6. **헤더 모드(4단계).** 인증된 시험 계정이 하나 이상이면 `test_account_passthrough`로 둔다(`evaluation_caller_passthrough`와 같은 동작, 승인 origin 요청에만). 외부 API 모드는 사전 공지·승인 기록이 있는 실행만. 아니면 `preserve` 그대로이고 세션 줄도 주지 않는다. `refresh_session`(계정 라벨만 받음, 연속 실패 3회·성공 시 초기화·계정별 최소 10초 간격)은 2의 같은 경로를 쓴다.

진행(2026-11-13): (a)를 구현했다 — `e2proxy.Rule.Purpose`(`auth_prep`)·`Call.AuthPrep`·`Execution.AddRedactValues`(8바이트 이상만, 응답 보류에는 안 씀)·정책 파일 `rules[].purpose`·지문. (b)의 엔진 쪽도 구현했다 — 실행 정책 `auth` 칸(로그인 방식·인증 준비 규칙 참조·계정별 자격 파일 pin)을 factory가 실행을 잡을 때 읽어 계정마다 한 번 로그인하고, 계정별 결과(`authenticated`·`login_failed`·`session_not_found`·`result_unknown`·`not_sent`)와 세션을 실행 옵션으로 넘긴다. 제품 쪽 실행 결속도 넣었다 — 실행을 만들 때 목록과 같은 판정으로 test이고 자격·로그인 방식이 있는 계정만 골라 실행 정책에 인증 준비 규칙·`auth` 칸을 넣고, 자격 사본을 결속 디렉터리에 해시로 고정한다(고른 계정·자격 해시가 결속 이름에 들어가 바뀌면 새 결속). 실행 중 확인은 결속한 계정이 지금도 같은 자격으로 test인지 보고, 아니면(해제·만료·판 변경·자격 교체) 새 송신을 멈춘다. 결속 뒤 새로 표시한 계정은 그 실행과 상관없다. 해제·철회·자격 교체 때 결속 디렉터리의 사본도 지운다. 실행 결과의 `account_auth` 칸도 실었다(실행 서비스 마감 → 준비 작업, 계약 §3.4). 남은 (b): 실행 중 결속 계정이 바뀌어 멈춘 경우의 정지 사유 표시.

(c) 1부도 넣었다 — E② 헤더 모드 `test_account_passthrough`(모델이 쓴 Cookie·Authorization을 승인 origin에 그대로, Set-Cookie 보류 안 함, 보호 값 반사 보류는 그대로, 평가 문맥 불가), 제품 결속이 시험 계정을 결속하면 이 모드로 두고 Worker system에 시험 계정 세션 줄을 준다. 대상이 응답으로 새로 발급한 세션(Set-Cookie 쿠키 값, Authentication-Info)은 모델에 그대로 가고, 응답을 넘기기 전에 출력 가림 목록에 더해 도구 출력·근거·활동 기록에는 남지 않는다(8바이트 이상 값은 출력 어디서든 값으로 가리고, 실행당 1024개를 넘으면 그 응답 보류. 8바이트보다 짧은 발급 값은 값으로 가릴 수 없어 그 응답을 보류한다 — curl 쿠키 파일처럼 헤더 줄이 아닌 모양으로 기록에 남을 수 있어서다. preserve 실행은 자격 응답을 늘 보류하므로 그보다 더 막지 않는다. 겹 방어로 시험 계정 실행의 출력에서는 Set-Cookie 줄의 쿠키 값 자리와 Authentication-Info 값도 구조로 가린다). 인증 준비에서 인증된 계정이 하나도 없으면 factory가 첫 모델 요청 전에 그 실행을 `preserve`처럼 묶는다(`Execution.DisableTestAccountPassthrough`, 되돌릴 수 없음; 정책 지문의 `header_mode`는 설정값 그대로이고 묶였는지는 `account_auth`로 드러난다). 서버는 정책을 읽을 때 `test_account_passthrough`면 `auth` 칸을 요구한다(제품 결속을 거치지 않는 정책 파일도 같음). 외부 API(openrouter) 실행은 운영자가 그 회차의 사전 공지·승인 진술(초안 입력 `external_test_accounts`, 화면 동의 문장과 서버 기록 문장이 같음)을 낸 실행만 시험 계정을 결속한다. 서버는 시작 전에 계정 저널에 동의(진술 해시·주체·시각·작업)를 남기고, 남기지 못하면 시작하지 않는다(`external_consent_unrecorded`). 진술이 없으면 제품 결속은 계정을 고르지 않고, 서버는 외부 API 모델이면 `auth` 칸이 있는 정책을 시작 때 거부한다(#552·#561·#568). 평가 러너는 이 모드를 받지 않는다(평가의 caller 자격 통과는 `evaluation_caller_passthrough`). `refresh_session`도 넣었다 — 시험 계정 세션이 있는 Worker에만 붙는 도구로 계정 라벨만 받고(세션 목록에 있는 라벨만 호스트로 넘김), 서버가 처음 인증 준비와 같은 경로(E② 인증 준비 규칙·비밀번호 보호 값 등록·새 세션 가림)로 다시 로그인한다. 성공 횟수 제한 없이 실행 전체의 계정별 연속 실패 3회·최소 10초 간격으로 제한한다(2026-11-16 보완, 아래). 다시 로그인도 그 실행의 E② 요청 예산을 쓴다. 성공하면 새 세션 헤더를 도구 결과로 모델에 주고(기록·활동은 실행 가림을 거침), 실패하면 결과 코드만 준다. 남은 것: S07 실제 회차 대조, 탐색 실행기 브라우저 프로필 세션, 보고서의 계정 로그인 실패·인증 뒤 영역 미검사 표시와 화면 표시 실제 회차 확인(S08), 대상 응답의 비세션 토큰(2단계 인증 설정 토큰) 분류와 모델 입력·DB 활동 기록 처리 결정(S09). 아래 "실제 회차 확인".

PR 순서: (a) E② 로그인 전용 규칙·`AuthPrep`·출력 가림 목록(E② 내부, 이동찬 페어 리뷰 필수) → (b) 서버 인증 준비·`account_auth`·실행 결속 → (c) `test_account_passthrough`·Worker 세션 줄·`refresh_session`·S07~S09 수용시험. (a)~(c)는 이동찬 또는 윤재상 승인 없이 머지하지 않는다.

## 재로그인 실패 기준 보완 (2026-11-16)

60초처럼 짧은 세션 수명에서도 계속 진단할 수 있게 누적 3회 상한을 연속 실패 기준으로 바꾼다. 대상·토큰 수명은 코드에 고정하지 않는다. #610의 토큰 검사 경로 전달과 별개로 적용된다.

- **성공:** 새 세션을 추출하고 출력 가림에 등록한 `authenticated`만 성공이다. 연속 실패 수를 0으로 만들고 공유 세션 저장소를 바꿔 다음 Worker도 새 헤더를 받는다. 성공 횟수에는 별도 상한이 없지만 기존 회차 시간·호출·요청 예산은 사용한다.
- **실패:** 입장을 허용한 재로그인이 새 세션을 주지 못하면 센다(`login_failed`, `session_not_found`, `result_unknown`, `not_sent`). 3회 연속이면 그 계정은 실행 종료까지 `refresh_limit`이다. 첫 인증 준비·알 수 없는 라벨·입장 전 취소는 세지 않는다. 자동 재시도는 없다.
- **간격:** 성공·실패 모두 이전 재로그인 완료부터 다음 시작까지 계정별 최소 10초다. 같은 계정의 동시 요청은 로그인과 세션 교체까지 직렬화하고, 뒤 요청은 간격에 걸리면 `refresh_cooldown`으로 끝낸다. 다른 계정은 독립적이다. 간격·실패 상한 거부는 E② call도 새로 만들지 않고 로그인 요청·예산을 쓰지 않으며 실패 수를 늘리지 않는다. 간격은 신뢰 호스트 기본값이고 모델·정책 파일의 조절 값이 아니다.
- **명령 실패와 Worker:** `refresh_limit`·`refresh_cooldown` 등 재로그인 실패 결과는 해당 도구 명령의 오류다. Worker는 다른 허용 작업을 계속한다. 전체 요청 예산 소진·권한 철회·결과 불명·감사 오류 등 기존 실행 정지 조건을 무효화하지 않는다. 실패한 계정으로 인증이 필요한 영역을 확인했다고 판정하지 않는다.

회귀 시험은 소유 로컬 HTTP 대상에서 가상 시계로 60초 토큰 만료·재로그인·새 토큰 GET을 8회 반복한다. 연속 실패 초기화·계정 분리·동시 요청·간격 경계·미송신 거부·세션 가림을 대조하고, 실제 SDK 세션에서 실패 도구 결과 뒤 다음 Bash 명령이 처리되는지 확인한다(모델·Bash 실행은 fixture). 실제 VAmPI 2차 회차와 외부 LLM 호출은 이 변경의 검증 범위 밖이다.

## E③ 시작 시 인증 결속 (2026-11-24 후속)

실행 결과의 `account_auth`는 최초 인증 준비 결과이며 재로그인으로 바꾸지 않는다. E③의 계정 역할 검사는 실행이 보유한 같은 `run_ref`의 현재 세션 결속을 다시 조회한다. 최초 준비에서 실패했더라도 모델 단계의 `refresh_session`이 실제 새 세션을 확보한 계정은 E③ 시작 대상으로 볼 수 있다. 반대로 최초 인증 성공만 있고 현재 세션 결속이 없으면 E③ 시작 대상으로 보지 않는다. 이 검사는 토큰의 현재 유효성이나 대상의 신원을 증명하지 않으므로 E③의 확정 직전 재로그인과 신원 경로 검증을 그대로 요구한다. 재로그인 실패·다른 회차 결속·동일 주체·증거 불일치에서는 확정 판정을 만들지 않는다.

## JWT 세션 조각의 기록 가림 (VAmPI 24b 후속)

> **2026-11-26 DLP 폐기로 없앰(이 절은 이전 기록이다).** 제품 기록은 내부 담당자만 보므로 대상이 발급한 세션 값을 가리지 않고, 모델 입력에도 넣을 수 있다(CLAUDE.md 절대규칙 2). 시험 계정 실행(`test_account_passthrough`)은 세션 값을 출력 가림 목록에 넣지 않고(`AddRedactValues`가 받기만 함), JWT 조각 등록·실행당 등록 칸(#840)·응답 발급 값 등록과 그 때문의 응답 보류·요청 자격 자리의 구조 가림도 없다. 저장 기록 가림(`RedactRecord`)은 E③ 표식과 우리 제어 비밀(설정한 보호 값)만 가린다. 시험 계정 실행이 아닌 실행의 출력 가림 전용 값(전체 값, 최대 64개)과 JSON 문자열 안 이스케이프 값 가림은 그대로다. 지금 규칙은 [비밀번호 응답 보호 계약](contracts/password-response-protection.md)에 있다.

인증 준비·`refresh_session`·응답 세션 회전에서 **이미 대상 발급 세션으로 추출한 값**만 다룬다.
`test_account_passthrough`에서 정규 base64url의 JSON 객체 머리·claims와 서명 구성을 확인한 JWT는 전체 값에 더해 payload·signature도 출력 가림 목록에 등록한다. 서명 없는 JWT는 `alg: none`과 빈 signature가 함께 있을 때만 형식으로 인정한다. 이 검사는 세션의 암호학적 진위·인가 판정이 아니다. opaque 세션은 전체 값만 가리고, 공통 머리·8바이트 미만 조각은 등록하지 않는다.

가림은 활동·도구 입력 기록·후보·보고서 등 `RedactOutput` 소비 경계에 적용한다. 모델에 허용된 세션은 바꾸지 않고, 응답 전체 보류용 보호 값 목록에도 조각을 넣지 않는다. 전체 값부터 긴 값 순으로 가리며, 유효한 JSON 문자열의 Unicode escape는 한 번 해석해 알려진 값만 가린다. JSON의 다른 필드·숫자·구조는 보존한다. 임의 재인코딩·중첩 표현 전체를 판별하는 범용 DLP는 아니다.

값당 8바이트~8KiB다. 인증 준비/갱신의 실행당 등록 칸은 서버가 회차 조건으로 계산한다(2026-11-21, 이전 64개): 계정 수 × 세션당 값 수(정규 JWT 3, 쿠키 방식은 쿠키마다 3) × (승인 구간 ÷ 최소 재로그인 간격 10초 + 1) + 확정 단계 다시 로그인 몫(확정 단계가 켜진 실행만, 계정마다 한 번), 상한 4,096. 확정 몫은 처음부터 떼어 두고 모델 단계(마감 전)는 칸 − 몫까지만 쓴다. 응답 발급 값은 계정 세션과 따로 세며 상한 1,024개다. 칸이 모자라 새 세션을 받지 않으면 진단 기록에 `session_redaction_capacity`와 누적 횟수를 남긴다. 중복은 상한을 추가 소모하지 않는다. JWT 조각까지 전부 등록할 수 없으면 한 배치를 일부만 등록하지 않는다. 인증 준비/갱신은 `session_not_found`와 함께 세션을 모델에 주지 않고, 응답 회전은 기존 `withheld` 경로를 쓴다. 비시험 계정 모드의 동작은 유지한다.

검증은 합성 JWS·소유한 `httptest` 인증 서버·일회용 PostgreSQL로 수행한다. Worker 활동 저장, 후보 저장, 내부/공유 HTML 보고서를 직접 읽는 독립 회귀시험은 실제 모델 진단·탐지 성능 또는 제품 Docker 수용시험으로 계산하지 않는다. 실제 Qwen 후속 회차는 별도 승인까지 `NOT_RUN`이다.

## 비밀번호 반사 응답의 구간 가림 (VAmPI 24b 후속)

11/23 갱신: 새 시험 계정 실행은 `auth.password_response: "model_visible_v1"`로 결속한다. 대상 응답에 비친 비밀번호를 보류·가림 없이 도구(모델)에 주고, 저장 기록 가림(`RedactRecord`)에서만 가린다. 일반 제어 비밀의 전체 보류는 그대로다. 이미 `mask_spans_v1`로 결속한 실행·정책 지문은 그대로 읽는다. 세부는 [반사 응답 보호 계약](contracts/password-response-protection.md) "model_visible_v1"을 따른다.

이전(11/23 전) 결속인 `auth.password_response: "mask_spans_v1"`는 지원한 본문 표현에서 호스트 등록 비밀번호와 일치한 구간만 가린다. 일반 제어 비밀과 검사 미지원 응답의 전체 보류·비밀번호 모델 입력 금지는 유지한다. 이전 실행의 칸 생략·정책 지문·계정 결속·보고서는 그대로 읽는다. 형식·상한·HTTP 정합성과 v2 `withheld` 의미는 [반사 응답 보호 계약](contracts/password-response-protection.md)을 따른다. E③ 표식 판정·저널 v3는 별도다.
