상태: **2026-11-14 필수 검토자 결정 반영 / 문서 재검토 대기 / 실행 코드·수용시험 NOT_RUN**.

사용자는 성능을 크게 깎는 C34·C35 통제를 완화하고 소유·진단 권한의 핵심 경계를 유지하는 방향을 승인했다.
이 문서는 필수 검토자의 구체적인 결정을 반영한다. 보관 API·조직 보관 정책·설치 판 migration 영수증·갱신 판/CAS를
완화의 선행 조건으로 두지 않는다. 이 문서 PR은 실행 코드를 변경하지 않으며 문서 병합과 실제 구현·수용 완료를 구분한다.

## 1. 유지할 네 가지 불변조건

1. DNS TXT 소유 증명과 본인 진술로 소유·진단 권한이 승인된 **exact origin(scheme/host/port)**에만 보낸다.
2. 실제 `target_policy`(포트·주소 대역·경로·메서드·금지 대상)를 매 실행과 실제 송신에 집행한다. metadata·loopback·보호 인프라 차단도 유지한다.
3. 권한 철회 즉시 관련 실행의 새 송신을 막는다. 새 DNS/TLS 증거로 철회를 우회하지 않는다.
4. 리다이렉트·재시도·실제 연결 목적지를 다시 검사한다. 기존 실행에 새 DNS/IP/TLS 증거를 섞지 않는다.

E② 감사 장애·격리 실패·예산 소진·제어 비밀 보호, 시험 계정 분류/외부 전송 동의·비밀번호 제외,
모델 호출 전 예약·결과 불명 쓰기 재전송 금지·E③ 판정/영속성 계약도 유지한다. UI 입력은 권한 증거를 대체하지 않는다.

현행 값과 §3·§4의 구현 예정 값을 구분한다. 별도 표기하지 않은 파일은 `cmd/first-controlled-diagnosis/` 아래다.

## 3. C34 결정 — 기본값 유지·상한 확대·활성 자리 계산·압축

1. **코드 상한만 확대하고 기본값은 유지한다.** 설치 `valid_for_hours` 상한 168 → **8760**,
   설치 `max_runs` 상한 1000 → **100000**, 대상 정책 `max_targets` 상한 64 → **1024**.
   실제 값은 설치 조직이 이 안에서 정한다. MaxInt/무제한을 두거나 기존 설치의 실제 값을 자동 확대하지 않는다.
2. **등록 상한은 활성 기록(`pending`·`approved`)만 센다.** 철회·만료 기록은 감사용으로 저널에 남기되
   자리를 차지하지 않으며 같은 origin을 다시 등록할 수 있다. 만료 시각을 반영하고 과거 권한·계정 분류를 복원하지 않는다.
3. **기동 때 준비 저널을 작업별 마지막 기록으로 압축한다.** 모든 작업의 마지막 기록을 남긴 새 저널을
   임시 파일 → fsync → rename으로 교체하며 현행과 같은 replay 검사를 통과해야 채택한다.
   실패하면 옛 저널을 보존하고 검증되지 않은 상태에서는 새 실행을 허용하지 않는다. head·무결성 기록과의 일치 및 중단 복구도 검증한다.
   `maxJobs`와 저널 크기 상한은 압축 구현 PR에서 함께 올리고 **수치와 메모리·replay 시간 상한 근거를 그 PR에 제시**한다.
   이 두 수치만 아직 미정이며 상한·활성 자리 계산 및 C35 구현의 선행 조건이 아니다.
   작업 자체는 지우지 않으므로 위임별 회차 수·예산 합·미정산 예약·Unknown은 남은 마지막 기록으로 계속 계산한다.
4. **이번 범위 제외:** archive·retire·cleanup API, 조직 보관 정책 필드, 설치 판 migration 영수증.
   압축 뒤에도 실제 저장 공간 문제가 관찰되면 별도로 정한다. 업데이트 뒤 과거 보고서를 못 여는 실제 재현은 별도 버그로 고친다.
   기존 pin 검사를 우회하거나 실행 중 파일을 조용히 교체하지 않는다.

## 4. C35 결정 — 실행 시작마다 DNS·TLS 증거 검증

1. **승인 당시 DNS 집합과 정확 일치 조건을 없앤다.** 매 시작 새로 해석하고 **중복 제거 뒤** 응답 수를 검사한다(상한 8 → **32**).
   풀린 주소 **전부**가 `checkDestinations`와 `target_policy`를 통과해야 시작하며 하나라도 밖이면 거부한다.
   그 실행은 검증 후 고른 주소 하나에 고정하고 실행 중 재결속하지 않는다. 승인 당시 주소 집합은 이력으로만 남긴다.
2. **승인 당시 SPKI와 정확 일치 조건을 없앤다.** 매 시작 고른 실제 주소로 TLS 신뢰 체인·hostname·유효 기간을 검증하고
   관찰한 SPKI를 그 실행 감사에 남긴다. 검증 생략·인증서 오류 무시는 허용하지 않으며 HTTP 평문 고지는 유지한다.
3. **TXT는 매 시작 재확인하고 캐시를 두지 않는다.** 소유 증명이자 철회 신호다. DNS 일시 실패·TXT 실패는 그 실행만 시작을 거부하고 사유를 남긴다.
4. **대상 승인 `valid_hours` 상한 24 → 720, 기본값 유지.** 실행마다 TLS를 검증하므로 승인 기간을 승인 당시 인증서 만료까지로 제한하던 조건은 없앤다.
5. **이번 범위 제외:** 갱신 판·append-only 갱신 이력·CAS. 승인 기록을 고치지 않고 실행마다 새 증거를 쓴다.
   이미 도는 실행은 시작 때 고정한 주소·SPKI로 끝까지 가며 새 증거가 섞이지 않는다. 철회는 기존 대상 기록 하나로 모든 새 송신을 막는다.
6. **재승인 때 시험 계정 분류 해제·외부 시험 계정 회차 동의 계약 유지.** DNS/TLS 갱신으로 계정·세션·외부 전송 승인을 재사용하는 새 권한을 만들지 않는다.

## 5. 호환성·실패 처리

| 상황 | 채택할 동작 |
|---|---|
| 기존 설치/대상 | 기본값·설정된 실제 값 유지. 코드 상한 확대만으로 실행 범위를 자동 확대하지 않음 |
| 압축 실패·디스크 부족·부분 기록·replay 불일치 | 옛 저널과 작업·예산 증거 보존, 검증 실패 시 새 실행 차단 |
| active·Unknown 작업 | 작업을 삭제하지 않고 마지막 기록·상태·반환/drain·예약 보존 |
| DNS/TLS/TXT/철회 상태 불명 | 해당 시작 거부·사유 기록. 옛 연결 증거 대체·정책 밖 주소 재시도 금지 |
| 시작·철회 경쟁 | 실제 송신 직전까지 철회 확인, 철회 뒤 새 송신 0을 소유 수신기로 검증 |
| 정상 주소 풀·인증서 교체 | 다음 실행은 새 검증 증거, 기존 실행은 시작 때 고정한 증거 사용 |
| 업데이트 뒤 보고서 열람 실패 | 실제 재현·과거 자료 보존을 포함한 별도 버그 수정. migration 체계를 완화 선행 조건으로 추가하지 않음 |
