# C34·C35 제품 수명·보관 정책과 대상 증거 갱신 결정안

상태: **팀 결정 대기 / 구현 BLOCKED**. 필수 검토자 **mminjun**, 공동 검토 jsang01.
기준: `origin/dev ca851b056111a4f28493a50d3be3e6cc80ffb9fd` (2026-11-13).
사용자는 C34·C35의 제약 완화 방향을 승인했다. 이 문서는 그 방향의 계약 선택지와 구현 전 검토 자료이며,
팀 승인 전에는 실행 권한·한도·pin·소유 증명·DNS/TLS 검사를 바꾸지 않는다. 새 상한 숫자를 정하지 않는다.
이 PR 병합이나 문서 작성만으로 C34·C35가 구현 완료되는 것은 아니다.

## 1. 유지할 네 가지 불변조건

1. 소유·진단 권한이 증명된 **exact origin(scheme/host/port)**만 승인한다.
2. 설치 조직의 실제 `target_policy`(포트·주소·경로·메서드·금지 대상)를 매 실행과 실제 송신에 집행한다.
3. 권한 철회가 살아 있는 동안 새 송신을 막는다. 갱신·캐시·다른 판을 통해 철회를 우회하지 않는다.
4. 리다이렉트·재시도·실제 연결 목적지를 다시 검사한다. 새 DNS/IP/TLS 증거는 기존 실행에 혼입하지 않는다.

E② 감사 장애·격리 실패·예산 소진·제어 비밀 보호, 시험 계정 분류/외부 전송 동의·비밀번호 제외,
모델 호출 전 예약·결과 불명 쓰기 재전송 금지·E③ 판정/영속성 계약도 그대로 유지한다.
브라우저 URL 입력이나 확인 상자는 이 불변조건을 대체하는 권한 증거가 아니다.

## 3. C34 제안 — 제품 수명 대신 조직 자원·보관 정책

권고안은 제품 설치 수명·역사 전체 개수와 실행 권한/예산을 분리하는 것이다. MaxInt나 임의의 더 큰 상수로 치환하지 않는다.

- 설치 조직이 보관 기간/용량·가용 디스크 여유·동시 활성 작업·등록 대상의 활성 용량을 정하는 보호 정책을 둔다.
  정책의 새 기본값·최대값·초과 시 경고/거절 기준은 **이번 문서에서 정하지 않으며 팀/조직 결정이 필요**하다.
  미구성 설치에는 현행 제한을 유지하고 무제한 권한을 자동 부여하지 않는다.
- terminal + 실제 반환/drain 확인 작업에만 `archive`를 허용한다. active·미확인 종료·관찰/보고서 작성 중은 정리하지 않는다.
  `retire`는 새 실행 대상에서 제외하고, `cleanup`은 조직 보관 정책/권한/참조 대조 후 자료를 회수한다.
- archive/tombstone/checkpoint에 소유자·승인 판·task/job/run 결속·누적 사용·미정산 예약·실행 횟수·철회 사실과
  감사 체인 연결을 남긴다. 수집 자료를 보관해도 비용이나 실행 횟수 예약이 초기화되지 않아야 한다.
- 보고서/E③ 근거·감사 보관의 참조가 있는 자료는 참조 보존/법정·조직 보관 정책을 확인한다.
  활성 실행의 파일·키·DB·감사 꼬리를 단순 삭제하지 않는다. 구체적인 원격 쓰기 API/역할은 승인 뒤 계약 PR로 정한다.
- 설치 업데이트에는 보호된 migration 영수증(이전/새 설치 판·허용된 호환성·검증 결과·실행 중 작업 처리)을 둔다.
  과거 승인/정책/보고서 읽기 자료는 불변 판으로 보관하고 새 실행은 새 설치 판에 명시적으로 결속한다.
  binary/helper/manifest pin을 무시하거나 기존 실행에 새 파일을 조용히 적용하지 않는다.
- 보고서 열람과 새 실행의 권위를 분리한다. 업데이트가 과거 보고서를 지우거나 새 대상/모델 권한을 만들면 안 된다.
  호환 판 로더를 제공할 수 없으면 변경을 거절하고 기존 자료를 보존한다.

## 4. C35 제안 — 소유 위임과 연결 증거를 새 실행용 불변 판으로 갱신

권고안은 **origin 소유·진단 위임**과 **연결 증거(DNS/IP/TLS)**의 수명을 나누고, 새 실행을 위한 검증된 갱신 판을 만드는 것이다.

- 보호된 갱신 권한은 인증된 승인자·same exact origin·현재 target_policy·철회 상태·원래 진단 위임 안에서만 행사한다.
  hostname/port/scheme/경로/메서드/쓰기 범위 변경은 연결 증거 refresh가 아니라 새 범위 승인이다.
- 새 DNS 응답 전체를 정규화·중복 제거하고 정책상 허용한 각 목적지와 보호 인프라/metadata/loopback/사설망 배제를 대조한다.
  조직 정책의 자원 상한은 별도 결정한다. IP 8개 제한을 없애는 것만으로 임의 IP를 승인하지 않는다.
- HTTPS는 실제 선택 목적지에 대해 신뢰 체인·hostname·기간을 검증한다. 정상 SPKI 교체도 새 판에만 기록한다.
  검증 생략·인증서 오류 무시·구 pin과 다르면 아무 값이나 저장하는 로직은 허용하지 않는다. HTTP 평문 고지는 유지한다.
- TXT 재확인을 줄이려면 권한 위임의 유효성/재확인 조건·회수 신호·실패 시 닫힘을 먼저 정해야 한다.
  캐시 TTL 숫자는 새로 정하지 않는다. 검증할 수 없는 소유 증명을 캐시 성공으로 대체하지 않는다.
- 후보 판 검증 후 보호된 append-only 갱신 이력(승인자·시각·원본/새 판·증거 유형·정책 판·검증 결과)에 원자적으로 저장한다.
  감사/저장 실패 시 새 실행에 채택하지 않는다. 병렬 refresh/revoke/start는 한 판을 CAS로 확정한다.
- 기존 실행의 승인·IP·SPKI·SourceDigest는 그대로다. 새 판은 새 실행에만 적용한다. 철회는 관련 판 전체의 새 송신을 막는다.
  기존 실행을 구 판으로 유지할지, refresh 때 안전하게 중지할지는 팀 결정이 필요하다. 어느 선택도 기존 연결 범위를 넓히지 않는다.
  구 판 보존이 없는 과도기에는 기존 실행을 fail-closed로 중지하며 새 증거로 자동 재개하지 않는다.
- 대상 재승인 시 계정 분류 해제/재인증·외부 시험 계정 회차 동의가 필요한 현재 계약은 유지한다.
  연결 증거 갱신을 통해 계정·세션·외부 전송 승인을 재사용하는 새 권한을 만들지 않는다.
