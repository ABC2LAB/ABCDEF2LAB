# 실행 결과·모델 쪽 결정안 (P3: C05~C12·C28)

상태: **결정안(2026-11-12, 최민준 결정·이동찬 리뷰).** 리뷰로 확정되기 전에는 구현하지 않는다. 일정은 적지 않는다. 측정 전 수치는 적지 않는다.

[개선 목록](control-restore-backlog.md)의 P3 중 최민준 담당(C05~C12·C28)을 한 번에 정한다. 원칙은 개발 계획 11/11 개선 순서의 "새 송신을 멈추는 경우"다. 자동으로 새 송신·모델 호출을 멈추는 것은 감사 저장 실패, E② 집행 장애, 격리 실패, 권한 철회·만료·결속 실패, 승인된 요청·시간·비용 예산 소진뿐이다. 그 밖의 실패는 **그 호출·그 intent만** 실패로 남기고 실행은 계속한다. 운영자 화면·보고서 표시는 이경준 몫(C04·C33~C35)이고, 여기서는 상태 값과 사유만 정한다.

## 1. 모델 호출

- **C05 — 모델 호출 오류 한 번이 실행을 막는다**(`server/first_diagnosis_model_budget.go` `after`).
  - 지금은 오류·사용량 불일치면 `blocked`와 `UsageKnown=false`를 세워 다음 호출을 모두 막는다.
  - 결정: 예약은 이미 상한으로 셌다(`Reserved*`). 실패한 호출은 **예약한 양을 쓴 것으로 계산**하고(`InputTokens += 예약 입력`, `OutputTokens += 예약 출력`, 비용은 예약 비용), 실행을 막지 않는다. 대신 `UnknownUsageCalls`를 하나 늘리고 사용량이 "상한 계산"임을 표시한다. 다음 호출의 예산 검사는 지금처럼 예약 합계로 한다.
  - 막는 경우는 그대로 둔다: 예산 소진, 영속 기록(`observe`) 실패, 외부 제공자 정책이 막힘(아래 C06의 설정 오류).
  - 실행 중 운영자 중지·대상 철회로 끊긴 호출은 "결과 불명"이 아니라 **중지**로 기록한다(문맥 취소가 원인이면 실행 결과는 `stopped`).
- **C06 — OpenRouter 200 아닌 응답 한 번에 영구 차단**(`llmpolicy/openrouter_transport.go`).
  - 결정: 응답을 셋으로 나눈다. ① 설정 오류(401·403·400 등 4xx, 응답 형식 위반)는 지금처럼 정책을 막는다. ② 일시 오류(429, 5xx, 연결 실패)는 그 호출만 실패로 두고 막지 않는다. 다시 보낼 때는 같은 예약 규칙(C05)으로 새로 예약한다. 연속 일시 오류 상한(설정 값, 기본은 제품 상한과 같은 방식으로 설치 설정에 둔다)에 닿으면 그때 막는다. ③ 정상 200은 지금과 같다.
  - 비용 대조(`next.CostMicros`)는 지금 그대로다. 일시 오류 호출의 비용은 제공자 통계로 확인되면 실제 값, 아니면 C05의 예약 비용으로 센다.
- **C07 — 유료 승인이 1회용**(`llmpolicy/openrouter_file_linux.go` `.used` 표식).
  - 지금은 승인 ID당 첫 송신만 허용해서 재시작 뒤 예산 재사용을 막는다.
  - 결정: 1회용 표식 대신 **승인별 누적 사용량 파일**(보호 디렉터리, 추가 쓰기만, 쓸 때마다 fsync)을 둔다. 같은 승인으로 여러 실행을 하되 승인의 총비용·만료 안에서만 허용한다. 재시작하면 파일을 읽어 남은 예산으로 시작한다. 파일을 읽을 수 없거나 형식이 깨졌으면 지금처럼 막는다(재사용 방지 목적 유지).
- **C28 — 호출을 하나씩, 호출마다 컨텍스트 전체를 예약**(`first_diagnosis_model_budget.go` `before`·`acquireCall`).
  - 결정 1: 입력 예약을 **컨텍스트 창 전체 대신 실제 요청 크기의 상한**으로 한다. 직렬화한 요청 바이트 수(+framing 여유)를 입력 토큰 상한으로 쓴다(토큰 하나는 1바이트 이상이므로 바이트 수가 토큰 수의 상한이다). 컨텍스트 창보다 크면 지금처럼 거부한다. 출력 예약은 지금처럼 `max_tokens`다.
  - 결정 2: 동시 호출 수를 설치 설정 값으로 둔다(기본은 지금과 같은 1). 예약·사용량 기록은 지금의 잠금 안에서 한 호출씩 처리하고, gate만 넓힌다.
  - 근거: 기록상 실제 사용과 예약이 크게 벌어진 회차가 있다([근거](url-diagnosis-preparation.md)). 이 결정은 예산 상한을 넓히지 않고 예약을 실제 상한에 맞추는 것이다.

## 2. 실행 결과

- **C08 — intent 하나·상한 도달이 실행 실패**(`server/first_diagnosis_supervisor.go` `generalCompletion`, `server/e2_http_runtime.go`).
  - 결정: intent 결과를 다섯으로 나눈다: `done`, `policy_limited`(E② 거부·미지원, 지금 있음), `incomplete`(턴 소진·시간 초과·Bash 미호출·일시 실패), `unknown`(결과 불명 송신이 있음), `stopped`(운영자 중지·철회). 실행 결과는 감사가 닫히면 **`complete`(모두 done·policy_limited) 또는 `partial`(incomplete·unknown이 섞임)** 이고, 실패가 아니다. 실패는 감사·E② 집행·격리·권한 실패뿐이다.
  - Planner 라운드·도구 호출 상한 도달은 실패가 아니라 **실행 마감 사유 `budget_limited`** 로 끝낸다. 찾은 후보·근거는 보존한다.
  - unknown intent의 쓰기 요청은 다시 보내지 않고(개발 계획), 그 intent에 기대는 후속 intent만 보류한다.
- **C09 — 마지막 호출 하나가 intent 결과를 정함**(`agent/e2_http.go` 마지막 분류).
  - 결정: intent 결과는 그 intent의 **모든 호출 분류를 모아서** 정한다(가장 강한 것: unknown > incomplete > policy_limited > done). 마지막 호출이 `tool_failure`여도 앞에서 완료한 호출의 관찰은 남긴다. trusted 대조(`EqualCallResults`)가 깨지면 그 intent만 `unknown`으로 두고, 감사 무결성이 깨진 경우(감사 저장 실패)만 실행을 멈춘다.
- **C10 — 진단 로그 실패·상태 조회 1회 실패가 실행 취소**(`cmd/first-controlled-diagnosis/url_preparation_runtime.go`).
  - 결정: 진단 로그(사람이 보는 운영 기록)는 감사가 아니다. 기록 실패는 경고와 누락 건수로 남기고 실행 결과를 `unknown`으로 바꾸지 않는다. 상태 조회 실패는 제한된 횟수로 다시 묻고(설정 값), 그래도 실패하면 그때 `unknown`이다. 감사 저널·E② 영수증 저장 실패는 지금처럼 멈춘다.
- **C11 — 준비 단계 대체 경로 없음**(`first_diagnosis_startup.go`, `first_diagnosis_supervisor.go`, `agent/planner.go`).
  - 결정 1: 목표 분해가 실패하거나 0개면 원본처럼 **원래 목표 하나로 계속**한다(분해는 도움이지 필수 단계가 아니다).
  - 결정 2: 첫 계획에서 intent가 0개면 실패가 아니라 **실행 마감 사유 `no_intents`** 로 끝낸다. Planner 입력의 "0개도 괜찮다"와 맞춘다. 저장소 오류로 못 읽은 경우만 실패다.
- **C12 — 깨진 intercept 정규식 하나가 모든 도구 호출을 막음**(`intercept/intercept.go`).
  - 사실: 저장 경로는 #86 이후 정규식을 검사해서, 깨진 규칙은 검사 전에 저장됐거나 DB를 직접 고친 행에서만 생긴다.
  - 결정: #86의 fail-closed는 유지한다(막는 규칙이 조용히 꺼지면 안 된다). 대신 ① 깨진 규칙이 **허용 규칙이면 그 규칙만 건너뛴다**(건너뛰어도 더 엄격해질 뿐이다) ② 막기·확인 규칙이면 지금처럼 막되, 판정에 규칙 ID와 고정 사유(`rule_invalid`)를 남겨 운영자가 그 규칙을 고칠 수 있게 한다 ③ 서버 시작 때 깨진 규칙 수를 경고로 남긴다.

## 3. 구현 순서

1. C11·C10(실패 범위를 좁히는 것, 상태 값 변화 없음).
2. C05·C28(모델 예산 회계). 예산 상한은 넓히지 않는다.
3. C06·C07(외부 제공자, OpenRouter 시험 대상 필요).
4. C08·C09(실행 결과 상태 값 `partial`·`budget_limited`·`no_intents`). 화면·보고서 표시(이경준)와 API 상태 값 합의가 필요하므로 상태 값을 먼저 계약으로 올리고 구현한다. C01(결과 불명 1건 전체 정지 제거, 이동찬)과 같은 상태를 다루므로 순서를 맞춘다.
5. C12.

## 4. 열린 항목

1. **상태 값 이름과 화면 표시**(이경준): `partial`·`budget_limited`·`no_intents`·`stopped`를 화면·보고서에서 어떻게 보일지.
2. **C01과의 관계**(이동찬): E② 결과 불명 1건 전체 정지를 없앨 때 intent `unknown` 처리(C08·C09)와 같은 규칙을 쓴다.
3. **설치 설정 값**(C32 담당 미정): 동시 모델 호출 수, 연속 일시 오류 상한, 상태 조회 재시도 수. 측정(P0) 전에는 지금 값 그대로 둔다.
