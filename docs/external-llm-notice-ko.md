# 외부 LLM 사용 진단 사전 공지·승인 양식

상태: 양식 초안. 기준 코드는 dev `b672962`(2026-11-06)이다. 엔진이 바뀌면 진단 전에 표를 다시 확인한다.

외부 LLM API로 웹앱을 진단할 때 고객사에 미리 보내고 승인받는 문서다. 공개 연습 대상의 평가 회차에는 쓰지 않는다. 이 양식이 법적으로 충분한지는 고객사 담당자와 법무가 확인한다.

**이 양식은 데이터 전송에 대한 고지·승인만 다룬다.** 진단 실행 승인이 아니다. 실제 대상 진단은 별도의 범위 승인을 받고, E②를 일반 진단 경로에 연결·검증하기 전까지 시작하지 않는다(3번 표 참고).

## 1. 외부 LLM 제공자로 가는 내용

모델이 명령을 제안하고 그 결과를 읽어 다음 행동을 정한다. 그래서 아래 내용은 **가리지 않은 원문으로** 제공자에게 간다. 대화가 길어지면 요약본도 간다.

| 무엇 | 구체적으로 | 언제 |
|---|---|---|
| 작업 설명·목표 | 대상 주소, 범위, 운영자가 적은 문장. 여기에 적은 계정·비밀번호도 그대로 간다 | 항상 |
| 실행한 명령문 | 요청 주소, 파라미터, 명령에 넣은 헤더·토큰·비밀번호 | 항상 |
| 대상의 응답 | 명령 출력에 나온 본문·상태 코드·헤더. 화면에 보이는 개인정보, 업무 데이터, 오류 메시지, 내부 주소, 응답에 섞인 API 키 | 항상 |
| 대상이 발급한 토큰·세션 | 로그인 응답의 토큰, 쿠키 | 명령이나 출력에 나타나면 |
| 기록된 트래픽 | 지난 요청·응답 원문(인증 헤더 포함). 한 번 조회에 요청 2500자·응답 4000자까지 보이지만, 이어 읽는 도구로 잘린 부분까지 전부 받을 수 있다 | 트래픽 기록이 켜져 있고 모델이 조회하면 |
| 진단 중 정리한 내용 | 발견한 사실, 자산 목록, 취약점 설명과 재현 방법 | 항상 |
| 같은 설치본의 다른 자산 | 자산 목록은 작업끼리 공유된다 | 그 설치본에 다른 진단 자료가 있으면 |

- 제공자는 엔진이 요청해서 받은 응답만 받는다. 대상 저장소를 직접 읽지는 않는다. 다만 취약점을 이용해 읽어 낸 다른 사용자 데이터도 응답이므로 함께 간다.
- 중계 서비스를 쓰면 중계 회사와 모델 호스팅 회사 둘 다 내용을 처리한다.
- 제공자 쪽의 보관·로그·학습은 우리가 통제하지 못한다. 보낸 내용은 회수할 수 없다.
- 엔진은 응답에서 민감 정보를 찾아 가리지 않는다. 데이터가 민감한지도 판별하지 않는다.

## 2. 그 밖에 나가는 곳

| 받는 곳 | 무엇 | 언제 |
|---|---|---|
| 진단 대상 서버 | 엔진의 요청. 대상 쪽 로그에 남는다 | 항상 |
| 대상이 아닌 외부 사이트 | 모델이 명령이나 웹 조회로 부른 주소와 거기에 넣은 내용 | 모델이 부르면. 아래 3번 참고 |
| 웹 검색 서비스(DuckDuckGo 계열, Brave, Tavily) | 검색어 | 설정에서 켰을 때. 기본은 꺼짐 |
| 알림 채널(이메일, webhook, Telegram, DingTalk, Feishu, WeCom) | 취약점 발견·상태 변경 알림 | 채널을 등록했을 때 |
| MCP 서버 | 도구 입력 | 서버를 등록했을 때 |
| GitHub | 최신 버전 조회. 대상 자료는 없다 | 운영자가 업데이트를 확인·실행할 때 |

로컬 LLM 모드를 고르면 1번의 전송은 없어지지만, 이 표의 경로는 그대로 남는다.

## 3. 지금 엔진의 통제 상태

| 항목 | 상태 |
|---|---|
| LLM 경로 선택 | 기본은 로컬 전용이다. 외부 API는 `ARTEX_LLM_POLICY_MODE=external`로 명시해야 켜진다 |
| 대상·메서드·요청량 제한(E②) | 코어는 있지만 일반 진단 경로에 연결되어 있지 않다. 모델이 정한 요청이 이 경계를 거치지 않는다 |
| 기본 차단 규칙 | 삭제 요청, 대량 삭제 경로 같은 패턴을 도구 호출에서 막는다. 패턴 기반이라 대상 범위를 보장하지 않는다 |
| 응답·프롬프트 가림 | 없다 |
| 진단 자료 자동 삭제 | 없다 |

## 4. 엔진 설치 서버에 남는 내용

| 무엇 | 내용 |
|---|---|
| 트래픽 저장소 | 기록 프록시를 거친 요청·응답 전체. 평문이고 가리지 않는다 |
| 대화 전사(`transcripts`) | 모델과 주고받은 내용 전체 |
| 작업 디렉터리(`tasks`) | 명령 출력과 중간 산출물 |
| 데이터베이스 | 작업, 발견 사실, 취약점, 차단된 도구 호출의 입력, LLM 설정(API 키 포함) |
| 작업 내보내기 파일 | 운영자가 내보내면 전사와 작업 디렉터리가 들어간다 |

## 5. 고객사가 정할 것

- [ ] 1번의 내용이 위에 적은 제공자로 가는 것을 승인한다.
- [ ] 진단 환경에 실제 사용자 데이터가 없다. 또는 있어도 전송을 승인할 권한이 있다.
- [ ] 2번의 선택 기능 중 쓸 것을 정했다.
- [ ] 진단 전용 테스트 계정을 제공하고, 진단 뒤 계정 삭제와 키·토큰 교체를 맡는다.
- [ ] 진단 기간과 시간대를 승인한다.

외부 전송을 승인할 수 없으면 로컬 LLM 모드를 쓴다. 제공자나 모델이 바뀌면 다시 승인받는다. 어느 쪽이든 범위 승인과 E② 조건은 그대로 필요하다.
