# Workbench 제품 UI

`/`가 유일한 제품 프런트엔드다. `/workbench`도 같은 컴포넌트를 표시한다. 기존 레일·여섯 화면·서랍·반응형·키보드 탐색과 `workbench.module.css`를 유지한다.

- 모든 데이터는 인증된 URL v2 서버에서 조회한다. 예시 전환·가짜 실행·더미 결과를 제공하지 않는다.
- 새 점검에서 URL을 입력하고, **외부 LLM 사용하기**를 누르면 모델명·API 키 입력이 열린다.
- 키는 별도 인증 설정 API에 등록한 뒤 입력란에서 지운다. 진단 초안·시작 본문·React store·브라우저 저장소에 넣지 않는다.
- 설치된 프로필의 모델·provider·토큰·USD 한도는 서버 승인 범위에서 확인한다. 명시적 시작 전에는 task·모델 호출·대상 송신을 만들지 않는다.
- 미설치·조회 실패·결과 불명 상태에서는 실행을 막는다. 일반 작업 생성 API로 fallback하지 않는다.
- 자산·전체 이력 등 미지원 기능은 미지원으로 표시한다. 일반 HTTP 후보를 확정 취약점으로 승격하지 않는다.

공용 API·영수증·판정·보고서 계약은 `src/lib/diagnosis/`에 보존했다. `store.ts`에는 테마·입력 prefill만 둔다. URL 실행 상태는 `live/urlDiagnosis.tsx`, 실제 화면은 `views/live/Url*.tsx`가 담당한다.

설치·Docker 경계·화면별 API는 [제품 설치 문서](../../../deploy/product/README.md)를 따른다. 합성 UI/엔진 검사와 실제 유료 모델 수용은 구분한다.
